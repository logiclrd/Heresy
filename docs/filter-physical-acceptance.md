# Reusable Filters — physical/manual acceptance log

## 13 October 2026: first hands-on pass (reported by tester)

This log records **user-observed results**, which must not be relabeled as GitHub CI measurements or as Windows-plus-Linux qualification. The originally reported exercises, with follow-up for case 10, were performed on the tester's desktop build; the specific host OS, sample rate and DSP load were not provided for this session. Broad automated algorithmic/PCM qualification is documented separately in [filter-design.md](filter-design.md) and [filter-realtime-qualification.md](filter-realtime-qualification.md).

Synthetic fixture measurements at 8 kHz (not expected to match the tester's file/configuration): dry **9.50**, Minimum **14.91**, Linear **72.50**, Maximum **130.09** samples, logged in [CI #38426120990](https://github.com/logiclrd/Heresy/actions/runs/38426120990). ## Focused remaining listening/visual observations

1. **Saturation drive — passed** — A near-clipped sample and Drive 2/5 yielded clearly audible warm saturation with approximately unchanged processed loudness. The filter reduced apparent level relative to the dry sample. No further manual distortion test is required for the v1 checklist; gain/harmonics are covered by PCM tests.
2. **FIR phase — passed** — The tester fixed the Channel/Note effect mismatch and analytically confirmed four distinct phases/treatments across 64 rendered ticks. The PCM-based island detector and relative energy-centroid assertions now preserve that outcome as an automated regression, alongside the existing standalone FIR phase-response tests. No further manual phase test is required for this checklist.
3. **Nested source (case 10) follow-on only** — Flattened-child channel Filter persistence versus private-mixdown isolation is now audibly **passed**. If undertaking extra coverage, add a sibling channel and instrument/note/channel/speaker Filter; check unrelated sibling processing, doubled master filtering, Note Off/Cut and tail truncation. This broader combination is optional additional coverage, not a reason to discard the passed isolation result.
4. **Speaker settings (case 11)** — With stereo/hard-pan use independent channels, then check settings persistence and legacy RC vs reusable Chain differentiation.
5. **Operating-system/overload (case 12)** — Exercise Linux and Windows with an expensive saturated Ladder + FIR combination at low and increased polyphony. High tap counts can exceed realtime deadlines, so an underrun under stress is not itself a DSP correctness failure. A crashed worker, unbounded diagnostics, corrupted audio, or failure to resume a lighter workload is a failure.

Physical filter-feature acceptance remains **open** in [todo.md](todo.md) solely for the still-unreported speaker-output case **11**, realtime-versus-export and Windows/Linux device case **12**, and any optional higher-cost/device acceptance. Manual cases **1–10 are passed** for their reported scopes, with the independently measured FIR phase/corrected effect routing recorded above. This report does not establish full Windows/Linux hardware certification or arbitrary-load realtime deadlines.
