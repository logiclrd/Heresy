## Focused remaining listening/visual observations

1. **Saturation drive — passed** — A near-clipped sample and Drive 2/5 yielded clearly audible warm saturation with approximately unchanged processed loudness. The filter reduced apparent level relative to the dry sample. No further manual distortion test is required for the v1 checklist; gain/harmonics are covered by PCM tests.
2. **FIR phase — scope-aware retest pending** — On the test Pattern with a persistent Channel Filter selected at row 16, change **Set Note Filter Stage Assignments** on rows 32/48 to **Set Channel Filter Stage Assignments** (using the actual stage name, e.g. `low.PhaseResponse = Minimum` and `low.PhaseResponse = Maximum`). Re-export the same 20-sample click experiment: distinct linear/minimum/maximum impulse waveforms are expected. If row 16 actually selected a *Note* Filter, a new event-local Filter must be selected on **each note** before that note's phase assignment; a one-row Note assignment cannot retune an earlier, already-completed note or all later notes. The new automated test confirms the correct Channel assignment works, while the mistaken Note command leaves Channel PCM unchanged.
3. **Nested source (case 10) follow-on only** — Flattened-child channel Filter persistence versus private-mixdown isolation is now audibly **passed**. If undertaking extra coverage, add a sibling channel and instrument/note/channel/speaker Filter; check unrelated sibling processing, doubled master filtering, Note Off/Cut and tail truncation. This broader combination is optional additional coverage, not a reason to discard the passed isolation result.
4. **Speaker settings (case 11)** — With stereo/hard-pan use independent channels, then check settings persistence and legacy RC vs reusable Chain differentiation.
5. **Operating-system/overload (case 12)** — Exercise Linux and Windows with an expensive saturated Ladder + FIR combination at low and increased polyphony. High tap counts can exceed realtime deadlines, so an underrun under stress is not itself a DSP correctness failure. A crashed worker, unbounded diagnostics, corrupted audio, or failure to resume a lighter workload is a failure.
