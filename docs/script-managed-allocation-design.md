# Script Pattern / Script Sequence code-isolation and allocation plan

**Status (2026-11-24):** This began as the owner-approved API isolation design for [issue #58](https://github.com/logiclrd/Heresy/issues/58). The production Pattern/Sequence capability gate, managed data, synchronous LINQ/lambdas and approved method groups are now implemented in [merged PR #67](https://github.com/logiclrd/Heresy/pull/67). The baseline [`script-runtime-allow-list.txt`](script-runtime-allow-list.txt) retains the owner's 2026-11-23 approved rules, extended by the owner's subsequent explicit approval of public types **defined in System.Linq.dll** (not other LINQ assemblies). The architecture protects application-level capabilities, **not an OS-enforced sandbox**. Relaxed ordering is a separate Pattern-only extension in [PR #69](https://github.com/logiclrd/Heresy/pull/69); see [the ordering contract](script-programmability.md#script-pattern-ordering-modes-issue-52-pr-69). User declarations and async execution remain unimplemented.

## Approved intent and threat model

- Script Patterns and Script Sequences should be able to compute with ordinary managed data. `new List<string>()`, dictionaries, strings, arrays, constructors on approved types, callbacks **within controlled execution**, `foreach`, and other ordinary C# computational features are reasonable authoring goals. The prior proposal to begin with primitive arrays alone, and its speculative 1 MiB / 32 MiB allocation quotas, **are superseded and withdrawn**.
- The threat is **unauthorized capabilities**: accessing files/processes/host services, reflection or unsafe memory, modifying protected process-global state, and escaping Heresy's intentionally restricted script API. Heavy CPU/memory consumption that a user deliberately requests on their own machine is primarily a self-inflicted performance problem, **not a sandbox violation**. Preserve existing musical work, runaway/cancellation and renderer boundaries; do **not** invent a byte quota as a security requirement.
- A second, distinct concern is **application containment**: deferred callbacks or finalizers may execute outside Heresy's catch/cleanup boundary and crash the process or race with retired state. The final selective blocks limit known routes. Do not overstate this as a guarantee of isolation: compiled managed code in the same .NET process is not an OS-enforced security sandbox.
- The requested policy is specifically for Pattern and Sequence scripts. Existing Envelope, parametric, and three expression-based Script Instrument contexts keep their current restrictions unless independently redesigned. The future procedural Instrument setup/per-note allocation policy is separate.
- `System.String::IsInterned` is intentionally **not blocked**. Inspection of Heresy's CLR intern pool is acceptable to the owner. The owner also explicitly prefers the blanket `System.Globalization.*` property-assignment restriction over trying to prove which aliased formatting objects were cloned.

## Authoritative policy interpretation

**Resolve names through Roslyn semantic symbols, never authored identifier spelling.** A fully qualified type name or a `using` alias must produce the same decision. “Roslyn tokens” in the owner's file is the requirement for *compiler-resolved identity*, not `SyntaxToken.Text` string matching.

1. Build a `ScriptApiPolicy` for `Pattern` and `Sequence`; retain a separate conservative policy for expression contexts. Resolve allowed types by the actual symbol's **metadata name, generic definition/arity, containing assembly**, and (where relevant) base type and interface chains. Confirm identity against the targeted .NET runtime's core library; do not let a third-party type spoof `System.Text.*` by declaring the same namespace. Explicitly handle runtime type forwarding so allowed symbols resolve to the intended implementation type.
2. The final file's lines are normative. `System.Collections.*`, `System.Collections.Generic.*`, `System.Collections.ObjectModel.*`, and `System.Text.*` describe approved categories of **runtime types**, not permissions for arbitrary third-party assemblies or unrestricted future API additions. `Calendar and all subclasses`, all enumerated types and all interfaces within `System.Private.CoreLib`, and CoreLib exception subclasses need dedicated assembly-aware matching; generic arity annotations (`\`1`, etc.) refer to **generic type definitions**.
3. Check *all referenced types*, including nested types, receiver types, type arguments, array elements, base classes, interfaces, type parameter constraints, cast targets, inferred types, and declared/returned members. `System.Type` and arbitrary `System.Reflection` symbols remain unavailable even if they are reachable as return types of an otherwise approved member. Never conclude “allowed” from the namespace of the receiver alone.
4. Check **operations and symbols**, not only `InvocationExpressionSyntax`: constructors and their overloads (including target-typed `new`), object/collection initializers, property/indexer getter and setter uses, fields, events, delegate creation/invocation and method-group conversions, conversions/operators, pattern/extension methods, `foreach` enumeration, deconstruction, `using` disposal, interpolation handlers, implicit compiler calls, and generic substitutions. Prefer traversing Roslyn `IOperation` together with the syntax tree and reject unrecognized operation kinds that could execute code.
5. Apply selectively blocked members to the **underlying resolved definition** across overloads, method-group conversions, inherited member use, and relevant overrides/interface dispatch. A blocked property means its getter (and any setter) must not be usable; the `System.Globalization.*` ban is specifically on **writes** (simple, compound, increment and equivalent lowered forms). Ban `CultureInfo` instantiation, file-path-bearing `StreamReader`/`StreamWriter` constructor overloads, and author-defined finalizers as specified. Do not infer a `Stream` permission simply because a reader/writer takes one as an argument.
6. Keep the owner-approved **exact exceptions**. In particular: `CancellationToken` and `CancellationTokenSource` are allowed; block token `Register` and `UnsafeRegister` (including overloads and method groups), and source `CancelAfter`. Timed constructors, `Cancel` and `CancelAsync` are not added to the deny-list; without allowed script callback registration these cannot independently schedule arbitrary script code. Block `TimeProvider.CreateTimer`, `ArrayPool<T>.Shared`, process-global culture/timezone cache mutations, `String.Intern` (but **not** `String.IsInterned`), specified delegate/reflection entry points, `Path.GetTempFileName`, specified file-path constructors, `Encoding.RegisterProvider` and `DateTimeFormatInfo.SetAllDateTimePatterns`. See the raw file for the complete authoritative list.
7. Block bypasses as **language capabilities**: unsafe code, raw pointers and function pointers, `dynamic` and late-bound dispatch, arbitrary `extern` / P/Invoke declarations, assembly/module initializers, arbitrary assembly references and preprocessor `#r`/`#load`, reflection invocation, and scripts defining types or members that avoid the generated wrapper's vetting. Allowing value-like `IntPtr` does not authorize pointer dereferencing or `Marshal`.
8. **Host boundary**: no host-owned `IServiceProvider`, `Stream`, editor objects, delegates, cancellation sources or other privileged object graphs are handed to scripts simply because they implement an approved interface. If a supported API ever receives such an object, audit its possible methods, retained references and aliasing separately. A list of *types* alone cannot establish ownership or lifetime isolation.
9. User-defined classes, structs, delegates and nested helper functions can be considered when the script source/wrapper layout supports their declarations. Constrain their accessible bases/interfaces and referenced members to this policy, prevent finalizers and unsafe static/module initialization, and decide the persistence of static state across Pattern/Sequence invocations. Their eventual implementation must not silently broaden this approved runtime list.

## Roslyn enforcement stages

1. **Catalog resolution**: derive a deterministic symbol-identity catalog from the exact owner source list; error on unknown or ambiguous policy entries rather than skipping them. Pin the target framework/runtime used for resolution and record policy version and source hash in tests. Keep every wildcard, inherited-type rule and selective exclusion traceable back to its literal source entry.
2. **Context-specific source validation**: parse authored source, disallow sandbox-breaking syntax/metadata, and validate the approved Pattern/Sequence language shape. Do not open previously rejected constructs in the expression contexts.
3. **Post-binding capability verification**: run semantic and `IOperation` checks on a valid generated wrapper. Require every executable user-origin operation and type to be allowed; include compiler-inserted work. Account for `#line` remapping, implicit operations and the compiler's diagnostics when projecting errors to authored spans. Do not let invalid semantic resolution accidentally turn a denied operation into an approved one.
4. **Trusted rewrites**: only after authored-source approval, perform existing loop checkpoint, incremental-yield and editor-F6 callsite rewrites. Generated-only `SequenceCallsite` constructors/overloads remain inaccessible to scripts. Audit the trusted rewrite surface so an allowed user construct cannot accidentally be reinterpreted as generated code.
5. **Runtime containment**: preserve per-invocation Pattern state, per-lookup Sequence locals, existing event limits and cancellation/error capture. Distinguish normal managed allocations from code running outside the script lifecycle. Treat the allow-list as application-level *code isolation*, not a process boundary.

## Adversarial acceptance plan

- **Positive Pattern tests**: create/use `List<string>`, `Dictionary<string,int>`, primitive/reference arrays of allowed types, strings and interpolation, safe constructor and initializer forms, `foreach`, local delegates and callbacks, generic methods, `using` for supported disposables, and numeric pitch math. Compare eager and incremental musical events, normal and editor-F6 source spans.
- **Positive Sequence tests**: build local collections each entry lookup; choose `Play` based on their contents; verify repeated invocation semantics, seeded `Random()`, non-script PCM equivalence, and the documented state lifetime.
- **Negative direct/indirect tests**: `File.Delete`, `Process.Start`, `Environment.Exit`, reflection, `typeof`/`GetType`, arbitrary assembly loads, forbidden constructor overloads, `Path.GetTempFileName`, culture property assignments and `SetAllDateTimePatterns`, `String.Intern`, `ArrayPool<T>.Shared`, timers and cancellation callback registration, finalizers, forbidden generic type arguments and alias-qualified names.
- **Delegate bypass tests**: `Action<string> action = System.IO.File.Delete` and `new Action<string>(System.IO.File.Delete)`; reject even if the resulting delegate `Invoke` is on an approved type. Test explicitly denied methods via aliases and approved inherited/interface overload dispatch.
- **Implicit execution tests**: user-defined conversion, property getter, indexer, `foreach` enumerator, `using` disposal, interpolated-string handler, compound assignment, method group, operator overload, constructor initializer and user-defined finalizer. Prove a forbidden target cannot hide in lowering.
- **Isolation/lifecycle tests**: reject host-owned reference escape and script-supplied entrypoints that bypass generated validation; ensure erroneous scripts cause the existing song-level diagnostic/failure path rather than corrupting a renderer session.
- **Compatibility**: established Script Instrument/Envelope/parametric restrictions, no new audio-callback allocations, no change to F6 trace losslessness or row/offset ordering, no silent dropping of valid notes.
- **Docs**: update `ScriptEditorHelp` and [script-programmability](script-programmability.md) with only implemented features; retain all approved types and blocks in [the raw allow-list](script-runtime-allow-list.txt).

## Implementation sequence and acceptance boundary

1. **Completed:** policy parser, assembly-identity/type/member checks and wrapper/author source containment.
2. **Completed:** canonical Roslyn operation validation before any trusted yield, loop or F6 rewrites; blocked framework/host entry points and exact approved helper members.
3. **Completed:** managed strings, arrays, collections, construction, synchronous `foreach`/`using`, inline lambdas, LINQ-to-Objects, and method groups of approved non-emitting methods.
4. **Completed in PR #67:** method-bound emission/callsite rewrites preserve shadowed helper names and F6 offsets; closing audit, exact-head CI and owner merge approval completed.
5. **Separate extension:** `#order relaxed` sorted preprocessing ([#52](https://github.com/logiclrd/Heresy/issues/52), PR #69) permits synchronous musical callbacks without changing the capability allow-list. Author-defined types/local functions, outliving/asynchronous callbacks, and unreviewed C# language shapes remain future work.

### Acceptance boundary

The owner's final attached file approves the **API policy** and the direction of code isolation; it does not pre-approve a claim that the compiler now safely runs unrestricted C#. Merged PR #67 includes approved managed strings, arrays, collections, `foreach`, synchronous `using`, inline lambdas, LINQ-to-Objects and **method-group conversions of approved non-emitting methods** in Pattern/Sequence contexts. Strict streaming still requires Pattern event generators to be direct statements; they cannot be called in lambda bodies or captured as method groups. PR #69 implements opt-in relaxed preprocessing for such emissions under the same policy. Async/outliving callbacks, user-authored declarations and other unreviewed forms remain restricted. Issue #58 was closed by the owner's merge of PR #67.
