# PR #12 — C5 realtime qualification and overload recovery

**Status (2026-11-15): C5(a–d) AUTOMATED ACCEPTED. C5 OPEN** pending C5(e–f), target-machine measurements, physical-device recovery and supported load limits. This document is subordinate to the [PR closing audit](synth-live-pr12-closing-audit.md). ## Acceptance boundary

The buffered audio architecture has **two distinct execution deadlines**: the PCM **producer** renders source/DSP blocks on a dedicated worker, and the OS/device **callback** copies already-prepared samples from a bounded ring. The off-PCM FIR/Multi preparation scheduler is a third distinct worker. A quick callback does **not** imply the producer met its deadline, nor that the buffer never ran dry. Conversely an intentionally over-budget producer block does not mean a callback deadline was missed when the ring had enough headroom.

Treat the following as different observations:

| Measurement | Already available in code | Scope |
| --- | --- | --- |
| Callback rendering duration, scheduling jitter, late callback starts, callback allocations | Existing `PlaybackRequestAudioSourceFactoryTests.PacedCallbacksProfileSustainedMultiExpansionWithoutHardwareDeadlineAssumptions` | *Simulated* 192 × 256-frame callbacks at 48 kHz; shared-runner scheduling diagnostic, not SDL/device measurement |
| Buffer underruns, number of buffered frames and recovery | `BufferedAudioOutputSource.UnderrunCount`, `BufferedFrames`; C5(a) controlled-stall test | One increment per short callback, not one per missing frame; no musical-clock advance on silence padding |
| Producer block count, output frames, sum/peak block time, blocks over render quantum budget | `BufferedAudioOutputSource` when constructed with `profileProducerRender:true` | Wall-time observations include OS preemption; counters disabled for normal playback; no hard guaranteed WCET |
| Off-PCM worker queue peak, completed/cancelled Multi expansions, number of prepared children, preparation time and allocations | `FirPreparationScheduler` diagnostics exposed by `BufferedAudioOutputSource` | Counter snapshots only; no guarantee that all candidate revisions finish before an audio callback |
| DSP throughput and source render allocations | `SynthProducerScalingProfileTests`, `SynthPairedRenderProfileTests`, `FmMixedFilterRealtimeQualificationTests` | Warmed/test-host diagnostics, not proof of actual device scheduling, ring level or click-free listening |
| Actual device callback underruns, recovery under 3→17→3 and worker saturation | **C5(e)** target-machine run required | Must record sample rate, buffer size, host CPU, backend, load and observed recovery; no inferred green result from CI |

### C5(a) — deterministic boundary recovery proof

`Heresy.Tests.Render.BufferedAudioDeadlineRecoveryTests` provides two new tests:

1. **Forced producer stall:** hold the *actual dedicated ring producer* inside its underlying `source.Render` while two device-facing callbacks request four frames each. Both callbacks return all-zero silence and produce precisely two underrun events. The callback makes **zero managed allocations** (measured after an initial warm call), does not call the source and consumes **no musical time**. The intentionally blocked 48-kHz four-frame producer block reports at least one over-budget block. After unblocking, the ring contains 1–16, then 17–32 original samples without skip/replay, missing frames, buffer-reset, session recreation or an additional underrun. The measured callback and producer elapsed times are printed, **never used as CI device deadlines**.
2. **Profiling isolation:** profile-enabled and ordinary 48-kHz buffered sources emit exactly the same sequence and each has zero underruns when prefilled; the ordinary source leaves producer timing counters at zero, while the opt-in profiled source reports actual rendered blocks and frames. Timing collection must not change PCM content.

This is **not** a stress reproduction of C5(c)'s 3→17→3 Multi state. Earlier renderer `FmSynthMultiRetirementTests.ThreeToSeventeenToThreeStopsAdvancingFourteenRetiredChildren` already verifies 14 excess children stop advancing after the transition and no steady PCM managed allocation; C5(c) must now connect that to actual producer throughput/recovery under *deliberate concurrent load and queued worker activity* instead of repeating the child-frame check alone.

### C5(b) — bounded FIR/Multi worker saturation, latest-wins and retiring-voice cancellation (2026-11-15)

**Automated ACCEPTED at test-only implementation HEAD** [`b07c876`](https://github.com/logiclrd/Heresy/commit/b07c876172b6ff5084a0e0c019ebd9c32bbce348). [**GitHub Actions #43735932634**](https://github.com/logiclrd/Heresy/actions/runs/43735932634) **COMPLETED SUCCESS: 3,818/3,818 tests** — Render **1,218**, Playback **357**, Core 911, Render.File 29, Scripting 105, UI 1,198; full Release, Windows apphost/icon, versioned release smoke and Linux ARM64. No renderer, transport, device callback or scheduler implementation change was necessary in this slice.

**Three distinct deterministic gates, not a 300-request CPU benchmark:**

1. **Worker admission cap and deferred retry.** `FirPreparationSchedulerTests.SaturatedMultiQueueRefusesExcessAdmissionButRecoversWhenDrained` parks the single dedicated preparation worker on a deliberately blocked first item, then admits exactly `FirPreparationScheduler.MaximumQueuedMultiExpansions = 64` pending Multi items. A further item is refused immediately while all queue slots are occupied. After unblocking, all admitted items complete and the rejected item can be enqueued and completed at the next producer-side opportunity. **Peak queue = 64; every candidate completes once, zero scheduler faults.** The queue cap limits *waiting* work and excludes the single already-dequeued active item; it is not a global per-note or voice-count ceiling. The test uses tiny tagged work items to prove **admission/retry semantics**, not to pretend they exercise real Multi DSP construction.
2. **FIR latest-wins across 12 distinct frozen mailboxes.** `FirPreparationSchedulerTests.ManyFirMailboxesCoalesceRapidSupersessionIntoLatestFrozenSnapshots` blocks the worker while twelve real FIR Filter-chain mailboxes each receive **25 newer numeric cutoff proposals**. No additional worker slot is enqueued per superseding revision; `TakeReady` is null until work completes, and each of the twelve eventually yields exactly one prepared kernel that matches its *last* frozen proposal, rejecting both its initial and immediately preceding cutoff. **Peak queued = 11** (the twelfth mailbox was already dequeued), **12 final preparations**, no faults. All cutoff snapshots are validated by `PreparedFirControlBatch.Matches`. This tests latest-wins and identity without inferring a device scheduling bound.
3. **Real held Synth retirement with a saturated queue.** `FmSynthPreparationSaturationTests.RetiredHeldNoteCancelsQueuedExpansionBehindSaturatedMultiWorker` starts an actual note with two Constant-backed Multi constituents, publishes a frozen **2→9** voice-count revision (past the four-voice audition reserve), verifies old **0.03125** PCM while its worker preparation is pending, and blocks that *actual* Multi request. It then fills all **64 waiting slots**, cuts the held note before the worker may construct children, and resumes the worker. The retired expansion is cancelled **once**, with **zero prepared Multi children** and no worker fault; all filler work drains, the rejected extra item retries, and a separately started new note produces actual latest nine-constituent PCM **0.140625** rather than resurrecting the retired note. **Peak queue = 64, cancellations = 1, abandoned prepared children = 0, completed filler/retry work = 65.** The retired voice's original PCM is not rebuilt on the worker; a new note is entitled to the current authored graph.

These gates are independent of CI-runner wall-time jitter: they coordinate on `ManualResetEventSlim` and assert completions, exact queue membership, frozen snapshot identity, original/new PCM and error/cancellation counts, **not** a millisecond threshold. The tests use `SpinWait` timeouts only to detect a stuck worker. The device callback remains the preexisting copy-only `BufferedAudioOutputSource.Render` path; C5(a) separately verified its zero managed allocation under an intentional producer stall. Off-PCM Multi construction may allocate; the assertion here is that cancelled obsolete work does **not** keep prepared child states alive, not that all worker construction is allocation-free.

**Bounded status:** C5(b) closes scheduler-admission, cross-mailbox FIR supersession and real cancelled-on-retirement queue saturation. It does **not** certify fairness under unlimited FIR traffic, real producer callback rate under 17 heavy Multi children, worker starvation under unbounded host load, or physical audio recovery. **C5(c)** must now measure same-held-note **3→17→3** retirement **and producer throughput recovery** (including a fresh-note comparison) under a deliberately overbudget interval; **C5(d)** combines mixed concurrent graphs, while C5(e/f) require device evidence and load-envelope decisions. **C5 stays unchecked**; C6 physical listening, C7 signoff, overall Synth TODO and PR #12 merge remain open.

### C5(c) — actual filtered Multi held-note 3→17→3, producer stall and recovery (2026-11-15)

**AUTOMATED ACCEPTED at implementation HEAD** [`0c71c05`](https://github.com/logiclrd/Heresy/commit/0c71c0506601db05fa144302d9c9c3381b0cfe18); [**GitHub Actions #43737563480**](https://github.com/logiclrd/Heresy/actions/runs/43737563480) **COMPLETED SUCCESS, 3,820/3,820 tests** (Core 911, Render.File 29, Scripting 105, Render 1,219, Playback 358, UI 1,198), full Release/Windows apphost/icon/versioned-release smoke and Linux ARM64 publication. All C5(c) changes are **test-only**: no production DSP, filter scheduler, playback session or device callback modification.

**Paired deterministic coverage (two new tests):**

1. `Heresy.Tests.Render.FmSynthMultiRetirementTests.FilteredThreeToSeventeenToThreeRetiresFourteenDspHistories` uses real three-stage OnePole Filter work under each of 17 Multi constituents. It retains an original 3-voice `FmSynthSound`, worker-prepares 17, advances all seventeen histories beyond the 100-ms fade, shrinks back to three with a second full fade, then snapshots each child invocation's `NextFrame`. On a further 1,024-frame same-note continuation, only the original three child clocks advance: **fourteen retired child clocks stay exactly unchanged**. The output remains a three-child filtered constant, and measured steady PCM allocates **zero managed bytes**. This is actual retirement, not merely gain-muting.
2. `Heresy.Tests.Playback.FmSynthBufferedRetirementRecoveryTests.HeldFilteredMultiRecoversProducerAfterSeventeenVoicesAndForcedUnderrun` creates a real `PlaybackRequestAudioSourceFactory` live Synth and a **profile-enabled** `BufferedAudioOutputSource`, 48-kHz mono, **256-frame ring / 64-frame producer quantum**. The *same original* live note starts with three serially-filtered child histories, receives immutable worker-prepared **3→17** revision beyond the +4 reserve (**one completed expansion, ten newly prepared child invocations**) and becomes audibly seventeen-voice. The test gates the real `source.Render` while seventeen are already sounding, completely drains the ring, verifies an actual short callback and **zero callback allocations**, and releases after an intentional >quantum stall. The original held seventeen-voice PCM resumes without a Note On. A frozen **17→3** revision then settles after its complete 100-ms fade; the original note stays alive with three contributing children and **zero** older-voice count. A *second* virtual channel begins a fresh note only afterward: its current three constituents sum with the original three to exactly six, and cutting it leaves the original three still sounding. The callback stays a ring-only reader; test adapter note forwarding was fixed during red-first testing, not in production.

**Exact-head shared-runner observations** (diagnostic, **never** a pass/fail milliseconds-per-frame assertion):

| Steady phase | Producer blocks | Frames | Measured producer µs/output frame | Producer blocks over nominal budget |
| --- | ---: | ---: | ---: | ---: |
| Original three | 12 | 768 | 3.992 | 0 |
| Expanded seventeen | 16 | 1,024 | 37.102 | 16 |
| Recovered three | 16 | 1,024 | 13.010 | 2 |

The whole deliberately stressed test reported **3 PCM underrun events**, **170 over-budget producer blocks** (across all phases, including deliberately gated periods), **29.763-ms peak block**, **0 callback-allocated bytes**, **1 completed Multi worker expansion**, **10 prepared children**, **0 cancelled expansions**, **peak worker queue 1**, **152,680 worker-allocated bytes** and **1.157-ms worker preparation time**. The ring refilled and subsequent stable PCM was finite and non-silent on the original note. The recovered three-voice measured cost was lower than seventeen (13.010 versus 37.102 µs/frame) but above the initial three (3.992 µs/frame); shared-host scheduling, preparation and measurement-window variation prohibit equating those figures with deterministic CPU cycle counts. **The direct child-clock test**, not elapsed time, proves the fourteen children were retired. The forced underrun is intentionally induced by a gate, not proof that 17 children universally miss device deadlines.

**Bounded signoff:** C5(c) has production buffered-pipeline stress/recovery evidence together with an explicit filter-backed retired-DSP-history assertion. It does **not** establish a realtime-safe voice limit, guaranteed physical-device recovery or sustained multi-note/nested-Filter loads. **C5(d)** still combines concurrent notes and interruption cases, **C5(e)** needs user's physical Linux/Windows observations, **C5(f)** records the validated load envelope; **C5 remains open**. C6 listening, C7 authorization, all-nonstructural Synth TODO and draft PR merge remain open.

### C5(d) — concurrent nested Multi/Filter, saturated worker, rapid revisions and independent interruptions (2026-11-15)

**AUTOMATED ACCEPTED at test-only implementation HEAD** [`717c954`](https://github.com/logiclrd/Heresy/commit/717c9543f5326a536f349628547ae8ee46fb2517); [**GitHub Actions #43740229544**](https://github.com/logiclrd/Heresy/actions/runs/43740229544) **COMPLETED SUCCESS, 3,822/3,822 tests** (Core **911**, Render.File **29**, Scripting **105**, Render **1,219**, Playback **360**, UserInterface **1,198**), full Release, Windows desktop/native/apphost/icon/versioned-release-bundle smoke and Linux ARM64 shared-codec publication. **No production renderer, worker scheduler, transport or device callback code was changed**; two new Playback regressions plus test-harness corrections only.

1. **Deterministic saturated worker with independently sounding, nested filtered owners** — `FmSynthConcurrentRevisionStressTests.SaturatedNestedMultiRevisionsRetireInterruptedOwnersAndKeepStickyOlderAudioCorrect`. Start **three independent original live virtual-channel notes**, each a Constant → **three-stage OnePole Filter** → **inner Multi(2)** → **outer Multi(2)**; assert initial 12 total constituent outputs. Publish frozen **inner 2→9**, park the actual nested Multi preparation on the off-PCM worker, fill **64 waiting slots** with real nested work and lightweight queue fillers, and verify no old-audio false positive while pending. Rapidly supersede with **9→12→4**; cut one owner and send **definite Note Off** to a sustainless second owner before preparation completes. The third original note continues producing its old two-inner-child audio while the queue is blocked. **Nested Multi children deliberately do not reserve the top-level +4 headroom**, so even final 2→4 requires worker preparation, bounded retry and atomic adoption; the regression does *not* pretend the latest 4 can commit directly. Once released, the queue drains/cancels stale requests, and the surviving old note settles at **four inner × two outer** with no stale result overwriting it. Start a fresh note on another owner using current four. Next add an **unreachable node** (intentional structural generation): two actually sounding old voices become sticky older, a new third voice starts current; a subsequent **compatible scalar edit** applies only to the current-generation voice and must not clear the older status. Cutting one older owner and definite Note Off on the other reduce older count independently; the new voice survives and then itself cuts cleanly. **Exact-head observations:** **peak waiting=64, cancelled Multi=4, prepared children=4, completed filler jobs=61, older counts 0→2→1→0**, no worker fault. All PCM/generation/retirement assertions are deterministic; worker timeouts detect deadlock only.
2. **Real dedicated buffered PCM producer with three concurrent owners** — `FmSynthBufferedConcurrentQualificationTests.ConcurrentFilteredNestedMultiLatestWinsAndOriginalNoteSurvivesInterruptions`. Use the actual live playback factory under `BufferedAudioOutputSource` with **48-kHz mono, 512-frame ring and 64-frame producer blocks**, profiled only in this test. Each note has Constant → **two-stage OnePole Filter** → inner Multi(2) → outer Multi(2). Publish nested **2→10→12** quickly and wait for all three held notes to emit the final *12×2-per-note* PCM: the worker completes **six actual nested expansions**, preparing **60 new child invocations**. Cut one owner and send definite Note Off to a sustainless second; the surviving original remains nonzero. Publish **12→3** and wait for the same original to settle without a Note On; start a fresh third-inner note alongside it and cut only the new owner, verifying the original persists. Assert finite, phase-correct steady levels, **zero false older voices**, **zero callback-managed allocations**, and no rendering fault. **Exact-head controlled/prebuffered observations:** **188 producer blocks, 12,032 produced frames, six worker completions, 60 prepared constituents, peak worker queue 6, 691,200 worker-allocated bytes, zero cancellations, zero underruns, 34 over-budget producer blocks, peak block 35.293 ms, zero callback-allocated bytes**. **Zero underruns here results from waiting for sufficient buffered PCM before reads; this is not a real-device deadline test.** The over-budget count also prevents claiming guaranteed realtime performance.

The first red-first run failed only because the test incorrectly assumed nested Multi reserve; the renderer explicitly limits reserve to eligible *top-level* Multis. After adjusting the worker-pending expectation, the exact implementation passed. The buffered test's first attempt was rejected because its two Filter stages had duplicate names; correcting the test fixture resolved that unrelated validation error. **Neither failure was evidence of a production DSP defect.**

**Bounded signoff:** C5(d) demonstrates multi-owner nested filtered DSP, queue saturation, rapid latest-wins proposals, interruption, live original-note recovery and sticky old-generation isolation together with real buffered producer measurements. This does **not** constitute unlimited-load fairness, release-envelope combinatoric coverage beyond previously accepted C4, actual device callback safety or a universal supported voice count. **C5(e)** still requires physical Linux and (where feasible) Windows audio/backend observations and **C5(f)** a documented target-machine load envelope/limitations. **C5, C6, C7, the overarching Synth TODO and the PR #12 merge remain OPEN.**

### Existing baseline profiles (do not duplicate)

The existing `PlaybackRequestAudioSourceFactoryTests.PacedCallbacksProfileSustainedMultiExpansionWithoutHardwareDeadlineAssumptions` runs a one-second mono 48-kHz, **8-note 2→64-Multi**, 192-callback paced simulation. It collects actual producer render-block and worker counters, callback jitter/cost/allocations, CPU, underruns and buffered-ring minimum; zero callback allocations and finite PCM are correctness requirements, whereas elapsed times and underruns are host-dependent **observations**. `BufferedLiveMultiBurstReportsWorkerCostsWithoutCallbackUnderruns` is a separate prebuffered controlled 6-voice 2→64 burst, and its zero underrun result is valid **only because each callback waits for enough already-written frames**. Other available performance evidence is in [profiling Synth graph CPU cost](synth-render-profiling.md) and [mixed Filter realtime qualification](filter-realtime-qualification.md), whose nine-stage/long-FIR cases **already miss their nominal 256-frame deadline on a shared runner**. No claim that heavy FIR, high voice counts or overbudget work can always render in realtime is permitted.
