# Tagged desktop release packaging

This document describes the automated release path, not the end-user guide.
The **source** README remains at [../README.md](../README.md). The
**end-user** README lives at [../release/README.md](../release/README.md)
and is copied into every published archive as `Heresy/README.md`.

## Trigger

To release version `1.2.3` from a verified commit on `main`:

```sh
git tag release-1.2.3
git push origin release-1.2.3
```

`.github/workflows/release.yml` starts on pushes of
`release-*` tags. Its validation job accepts **only** the exact
`release-A.B.C` form with three nonnegative decimal integers and
no leading zeroes. Invalid matching tags fail validation without
publishing artifacts. No release tag is generated by CI automatically;
the publisher chooses the tagged commit and version.

## Build matrix and archive names

All artifacts are **self-contained** `.NET 10` desktop publishes
(`UseAppHost=true`), built from the checked-out tag:

| Runtime identifier | Release asset | CPU / operating system |
|---|---|---|
| `win-x64` | `Heresy-A.B.C-win-x64.zip` | Windows x64 |
| `win-arm64` | `Heresy-A.B.C-win-arm64.zip` | Windows ARM64 |
| `linux-x64` | `Heresy-A.B.C-linux-x64.tar.bz2` | Linux x64 |
| `linux-arm64` | `Heresy-A.B.C-linux-arm64.tar.bz2` | Linux ARM64 |
| `osx-x64` | `Heresy-A.B.C-osx-x64.zip` | Intel macOS |
| `osx-arm64` | `Heresy-A.B.C-osx-arm64.zip` | Apple Silicon macOS |

The `Heresy` folder in each archive holds the complete `dotnet
publish` output, `README.md`, and `BUILD-COMMIT.txt`. That last file
contains the **40-character Git commit SHA**, obtained from the
runner's checked-out HEAD—not a branch name or an abbreviated hash.

The `Version` and informational version for each Heresy assembly
are set to `A.B.C`; `AssemblyVersion` and `FileVersion` are
`A.B.C.0` as required by four-component assembly version metadata.
`IncludeSourceRevisionInInformationalVersion=false` prevents an
automatically appended source-hash suffix; the separate provenance
file records the exact SHA. Every Heresy assembly is checked after
publish by `build/ReleaseVersionCheck` using assembly metadata.

## Publication and checks

Each matrix worker uploads one named Actions artifact.
The final job only runs if **all six** package jobs succeed, downloads
them, and creates or updates the tag's GitHub Release with the six
assets. The token needs `contents: write` permission only for that
release-publishing job; build jobs use read-only access.

The normal `main` CI workflow also smoke-tests a **self-contained
Linux x64 release publish** with version `1.2.3`: verifies embedded
metadata, builds a `.tar.bz2`, checks archive integrity, checks
the included end-user README, and compares the packaged commit SHA
with the checked-out commit.

This is a cross-platform **publish** process, not a signing,
notarization or graphical desktop smoke-test process. In particular,
the macOS ZIP contains a standalone executable directory rather than
a `.app` bundle. Hardware-dependent surround playback and codecs
still require the separate physical validation in
[the TODO list](todo.md).

Do not create a production release tag until the tagged commit's
normal CI is green. Creating a release tag is a publishing action;
no automatic tag was created while implementing this workflow.


## Linux ARM64 shared codec staging

The `org.sndfile.runtime.linux-arm64` NuGet **1.2.2.1** archive
contains static `.a` libraries exclusively; the x64 variant also
contains `.so` shared libraries. Static archives are not executable
runtime dependencies and cannot be renamed into `.so` files.

The Linux ARM64 release job runs on GitHub's native
`ubuntu-24.04-arm` runner, installs the Ubuntu ARM64
`libsndfile1` shared runtime and its codec dependencies, and runs
`build/stage-linux-arm64-sndfile.py` after `dotnet publish`.
The staging script copies libsndfile's **transitive non-glibc shared
dependency closure**, preserves required SONAME filenames, sets
`$ORIGIN` RPATH on the staged ELF files, and verifies that all
bundled shared dependencies resolve from the publish directory.
It also copies available Ubuntu package copyright notices into the
archive's `THIRD-PARTY-LICENSES` directory. It checks that each
staged ELF binary is really `AArch64` and rejects missing libraries.

The old x64 SONAME alias copies in `SndFileNativeRuntime.targets`
remain x64-specific; ARM64 must not accidentally attempt to duplicate
nonexistent unversioned `.so` files or ship static archives in their
place. A native ARM64 CI smoke job verifies the actual publish,
staged shared binaries, package archive and commit provenance before
the next release is tagged.

The Linux ARM64 build links against Ubuntu 24.04 libraries; other
Linux distributions may require a sufficiently recent glibc and other
standard system services. This is not a claim of universal Linux
distribution binary compatibility.
