# Reusable filters — design contract

Status: **incremental implementation** (11 October 2026). The Core filter-type catalogue, parameter descriptors, Filter SongObject definition model, and independently configured stage instances/chains are implemented. The six-root Filters document tree and four-column Avalonia layout (including four-/five-root migration) are also implemented. Filter definitions now round-trip through .hm.json/.hm and frozen song snapshots; configured instances/chains have reusable ID-based codecs and a validated import/remapping service. The standalone Filter definition editor and + Filter creation action are implemented. The embeddable Filter instance parameter editor and copy-on-write authoring session are implemented. A separate streaming Render engine, explicit bypass processor, state/transition contract, One-Pole low/high-pass, all seven Audio EQ Biquads, all four SVF responses, both linear and saturated four-pole ladders, first-/second-order All-Pass phase shifting, both feedback IIR and feedforward FIR combs, and all four standard FIR responses in **Linear, Minimum and Maximum** phase modes are implemented. FM Filter-node authoring, stable dynamic ports, independent per-note DSP, authored Tail processing, per-use editing, import and version-one graph persistence are implemented; audio-rate modulation fast-path optimization and rendered connections to Instrument tones and other hosts remain outstanding in [todo.md](todo.md). Current code still has the tracker-compatible ResonantFilterState and the limited final-speaker low/high-pass filters; neither has been replaced.

## Intent and governing constraints

Provide reusable, serial FIR/IIR filter processing in FM graphs, Instrument tone specifications, scripted/data Pattern note events, persistent physical/virtual playback channels, and final speaker outputs. The same definition and parameter-description machinery must serve editors, native commands, script-produced commands, persistence, and rendering.

Preserve the production lazy incremental recursive renderer, frozen song snapshots, sample-accurate event ordering, deterministic replay/seek, finite bounded work, the realtime PCM producer/ring boundary, private-mixdown isolation, and the existing physical/flattened source ownership rules. No DSP design or coefficient regeneration runs in the SDL callback. Do not create pre-rendered song buffers or future-event journals.

## Filter catalogue

The selector contains nonselectable grouping rows (indented entries are children). The two principal sections communicate relative computational cost, not a runtime guarantee:

- **Infinite Impulse Response (IIR) (Cheap)** — nonselectable
  - **State Variable Filter (SVF)** — nonselectable
    - Low-Pass
    - High-Pass
    - Band-Pass
    - Band-Stop (Notch)
  - **Audio EQ Biquads** — nonselectable
    - Low-Pass (12 dB/octave)
    - High-Pass (12 dB/octave)
    - Low Shelf
    - High Shelf
    - Peaking / Bell EQ
    - Band-Pass
    - Band-Stop (Notch)
  - Ladder (linear)
  - Ladder (non-linear/saturated)
  - All-Pass (Phase Shift)
  - One-Pole (6 dB/octave)
  - Comb (feedback)
- **Finite Impulse Response (FIR) (Expensive)** — nonselectable
  - **Standard Arbitrary FIR** — nonselectable
    - Low-Pass
    - High-Pass
    - Band-Pass
    - Band-Stop (Notch)
  - Comb (feedforward)

Hilbert Transformer and Half-Band are excluded from this pass. Comb feedback is IIR; comb feedforward is FIR. Linear and nonlinear ladders are deliberately distinct selectable types.

The SVF menu is symmetrical with the biquad submenu, but its four response types may share one internal SVF implementation with an immutable response selector. A two-pole SVF low-pass is not necessarily a new transfer-function family versus a low-pass biquad: both can produce equivalent linear responses. SVF topology has different numerical and modulation characteristics, notably for fast cutoff/resonance modulation. Favor a stable topology-preserving/TPT formulation. There is no requirement to expose SVF response selection as an audio-rate graph input.

Each selectable filter type has an explicitly specified algorithm, numeric constraints, meaningful defaults, parameters, and response/tail tests before that type is marked implemented. Configure nonlinear ladder saturation/drive and oversampling policy explicitly; define all-pass order, and comb delay/feedforward/feedback gain and stability constraints. Avoid claiming all types cost the same.

## Implemented Core parameter contract (initial catalogue milestone)

Core entry points: `Heresy.Core.Filters.FilterCatalogue`, `FilterKind`, `FilterMenuItem`, `FilterParameterDescriptor`, `FilterParameterValue`, `IFilterSpecificationInstance`, and `FilterSpecificationInstance`. The 21 selectable kinds are represented by distinct enum values, while nonselectable category rows exist only in the menu. Descriptors are shared immutable schema objects with canonical property names, units, bounds, defaults, numeric-versus-enum type and continuous-versus-structural classification. Instances use case-insensitive descriptor lookup; choice input is canonicalized on assignment. Batch assignment rejects duplicates and validates before commit. This milestone intentionally does **not** introduce a `SongObject` Filter definition, serialization, DSP state or playback wiring.

Band-edge cross-validation is atomic, allowing a simultaneous change to both bounds even where a one-at-a-time edit would be temporarily invalid. No DSP behaviour is claimed solely by selecting these initial metadata values.

## Object model and ownership

Three distinct layers:

1. **Filter definition:** a shared SongObject with stable ObjectId, an ordered nonempty list of filter specifications (stages). Each stage has a stable stage identity, unique user-visible name, and selectable filter type. Processing order is serial: output of each stage feeds the next. Names are unique within one definition under a case-insensitive comparison, and are valid unambiguous parameter-path identifiers; rename/reorder preserves stable stage identity.
2. **Filter specification instance / Filter instance:** a filter specification instance identifies one stage of a definition and holds that stage's configured parameter values, distinct from the definition's defaults. A Filter instance references a definition and supplies specification instances for every stage; multiple uses of one definition are independent. One use may have overrides while another uses defaults. A filter chain is an ordered collection of such filter instances/layers.
3. **Processing state:** one privately owned mutable DSP state for each actual processing invocation, stage, and PCM channel: FIR delay lines, IIR integrators/histories, coefficients, smoothing and optional tail accounting. Never share mutable histories between separate live notes or between independently routed speaker streams, even if they share a definition or parameter instance.

Filter definitions are distinct from configured uses, which are distinct from processing histories. Immutable prepared data (validated coefficient sets) may be shared only when safe. Do not store per-voice DSP history in the song. For nested Instruments, compose ordered filter *layers*, not one flattening scalar property: innermost tone processing first, then outer tone layers, then any explicit note-event filter, and finally the physical channel's persistent filter. A source's filter layers are not overwritten by adding an outer layer.

An instrument selecting another Instrument composes filters in this order. For flattened recursive Pattern/Sequence sources, project inherited note-level layers into independently processed descendant voices; retain their own histories and logical instigation/cancellation semantics, not a new independent clock. A deliberately combined nested mix must use the existing private mixdown, which owns its own channel context. Do not silently change flattening into mixdown merely to realize filters.

The interface to a filter specification instance must enumerate descriptors and get/set by the same canonical name. Descriptors specify name, value kind (finite numeric / enum / other explicit typed choice), units, range/validation, default, processing relevance, and whether the parameter is continuously modulatable or structural. Parameter name reuse across *different selectable types* is permitted; one instance has only one active type. Internal field storage may share fields across types without duplicating semantically identical parameters. Lookup by a stable stage ID is preferable in persisted graph links, while UI and command text use stageName.parameterName (e.g. stage1.CutoffHz). A stage rename must update or invalidate text/links explicitly, never silently retarget them.

Parameter changes and definition edits are validated atomically. In-place edits to a shared definition update the definition for all references in future snapshots while preserving independent per-instance overrides for still-compatible stage IDs/parameters. Removed/changed stages cause invalid graph ports/bindings to be surfaced and repaired, not silently reconnected. Editing an active song must not mutate an already-frozen playback snapshot.

## Implemented reusable definition and instance model

Core types: `Heresy.Core.Filters.FilterStageDefinition`, `FilterDefinition`, `FilterInstance`, `ConfiguredFilterStage`, and `FilterChain`. The definition extends `SongObject` and uses the reserved `SongObjectKind.Filter` identity. **Filter definitions can now be added to SongDocument**: the six-root Filters section and four-/five-root migration are implemented. Filter definitions can now be saved and cloned in isolated snapshots, but creation and editing are deliberately not yet exposed through the UI because the standalone definition editor remains outstanding.

A new definition has one valid `stage1` One-Pole stage; all definitions must remain nonempty. Stages have positive integer IDs, validated unique case-insensitive ASCII identifier names (no ambiguous dots in parameter paths), an independently selected `FilterKind`, and a complete read-only validated set of default parameter values. The definition supports validated atomic `ReplaceStages`, add/remove/rename/reorder/type change and default updates. Automatically assigned stage IDs never reuse deleted IDs. Renaming or moving a stage does not change its ID. Each explicit stage type change advances a generation, so per-use overrides tied to the old type cannot unexpectedly reappear if the type changes back or a stage ID is removed/reintroduced.

`FilterInstance` references a shared `FilterDefinition` (also exposing its stable ObjectId), and stores only explicitly configured stage overrides. Effective stage parameters inherit current definition defaults unless overridden, preserving independence across uses; resolving stages follows the definition's current serial ordering and names. The stage-parameter getters supply *independent* mutable snapshots; writing to one returned parameter object cannot modify the definition or a different instance. Atomic batch updates validate the effective configuration before committing overrides. Copies do not share mutable overrides. `FilterChain` composes independently owned layers in **inner-to-outer processing order**, preserving recursive Instrument nesting without flattening filters into one set of parameters. Chains are configuration objects, **not DSP history**.

These models are Core-only authoring/definition types. No DSP or graph node is wired to them yet. Persisted Filter instance overrides use stable stage ID and Filter ObjectId, never mutable stage index/name or in-memory definition references. The sample-rate-dependent DSP state belongs exclusively to separate render-time processing instances.

## Implemented persistence, snapshots and import

`SongDocumentJson` now recognizes Filter song objects in the **existing version-one** flat object table. Each serialized definition contains its ordered named stages, canonical filter kinds, validated typed parameter defaults, the monotonic `nextStageId` allocator and a complete `stageGenerations` record (including removed stage identities). This prevents old per-use overrides reappearing after a stage changes kind twice or an old ID is reintroduced. Four-/five-root migration remains independent of object serialization. Both `.hm.json` and packaged `.hm` use the same codec.

`SongDocumentSnapshot.Create` now deep-copies Filter definitions via normal JSON round-trip. Later authoring changes do not touch already-captured snapshots, and snapshot creation does not advance document or audio revisions. A `filter` tombstone kind is persisted and loaded for deleted definitions; a configured use that references a missing/deleted definition is **rejected explicitly**, not silently rebound to another object.

Configurable uses have public helper entry points:

- `SongDocumentJson.SerializeFilterInstance(FilterInstance)`
- `SongDocumentJson.DeserializeFilterInstance(string, SongDocument, optional ID remap)`
- `SongDocumentJson.SerializeFilterChain(FilterChain)`
- `SongDocumentJson.DeserializeFilterChain(string, SongDocument, optional ID remap)`

These codecs persist a Filter ObjectId, stage ID, filter kind, type-generation and **only explicit parameter overrides**; a layer's inherited stage defaults remain in its shared definition. Each deserialized layer is a new independent configuration. The chain preserves inner-to-outer ordering; invalid IDs, kinds, values, conflicting generations or duplicate override blocks fail as invalid data before exposing any partially built configuration. Processing-state histories are deliberately excluded.

`FilterDocumentImport.LoadImportSource` and `ImportFromSong` provide a framework-independent import of selected Filter definitions from another song, with new destination ObjectIds, copied immutable defaults and stage identity history, and an old-to-new ID map for deserializing associated configurations/chains. Missing selections reject before target mutation; unrelated definitions are not imported. The import service is **not yet exposed through a UI command**. No existing Instrument/Pattern/FM object currently contains a new Filter instance or chain: those integration milestones must use the codecs above when they introduce those references. Likewise, recording new Filter references in the generic song reference analyser belongs to the milestone that introduces their owning fields. Do not mistake availability of the codec for completed live playback integration.

Regression coverage: `FilterPersistenceTests` and `FilterImportTests` plus existing snapshot/JSON/module/document-tree tests. The schema remains `version: 1`.

## Implemented standalone Filter definition editor

`FilterDocumentEditor` and `FilterEditorControl` expose shared reusable Filter definitions in the sixth Filters pane. The **+ Filter** action creates one serial One-Pole stage under the root; double-click and **Edit Filter...** activate the standalone editor, with **← Document** returning to the same tree placement. Definitions can be renamed through the existing tree rename command. The stage list supports add, remove (but not the final stage), move up/down, unique case-insensitive names, type change, and all per-type default parameters. Stage IDs remain stable through reorder and rename. Changing a stage kind resets its incompatible defaults and increments the type generation.

The type selector is derived directly from `FilterCatalogue.MenuItems`, including all 21 selectable kinds and five disabled hierarchy headings: **IIR**, **SVF**, **Audio EQ Biquads**, **FIR**, and **Standard Arbitrary FIR**. Choices, units, finite numeric values and bounds are generated from the shared parameter descriptors. Structural parameters are editable here but are not audio-rate FM controls. The edit form builds a full candidate stage, validates every field and interdependent values, and commits it as **one atomic definition edit**; invalid data and no-op edits do not advance revisions. A real stage edit advances both `DocumentRevision` and `AudioRevision`.

Stage form fields are local drafts until **Apply stage**. Switching stages, adding/removing or moving stages is blocked while the current form has unsaved edits; **Reload shared stage** intentionally abandons the draft. A concurrent edit or reorder of the same shared stage list preserves the draft and rejects stale Apply with a reload message instead of overwriting another editor's changes. Authoring actions verify the definition still belongs to the active song; closing/opening a new song cannot mutate a stale editor's old definition.

This milestone edits shared definition defaults only. It does not yet introduce the distinct per-use `FilterInstance` parameter editor, filter DSP state, or downstream note/FM/Instrument integration. The dropdown shows all declared types, but those types do **not** generate audio until their DSP implementation milestones land.

## Implemented Filter-instance parameter editor (per-use configuration)

`FilterInstanceEditorControl` is an embeddable, headless-tested Avalonia editor for **one configured use**, distinct from `FilterEditorControl` (which edits shared definition defaults). It projects the definition's serial stages by stable stage ID, with each active parameter supplied from `FilterCatalogue.GetParameters`. Each parameter has its own **Override** checkbox: unchecked means inherit the current shared default and disables its value input; checked means persist an explicit override, even when its value happens to equal the current default. The UI shows the inherited default and authored range, units, odd/integer restrictions, and distinguishes continuously modulatable numbers from structural numbers/enumerated selections. A type selection does **not** appear in this editor, because the stage kind belongs to the shared Filter definition.

`FilterInstance.ReplaceStageOverrides(stageId, assignments)` provides **atomic replacement of the complete override set** for one stage. Unspecified parameters revert to inherited defaults; numeric/choice validation and FIR band-edge combinations are checked together before any mutation. A semantic no-op returns `false` and does not advance the per-instance `Revision` counter. Cloning creates an independent configuration, not independent shared definition defaults. Existing incremental `SetStageParameters` remains valid and also advances the revision only for changed explicit overrides.

`FilterInstanceEditSession(Func<FilterInstance> readCurrent, Action<FilterInstance> publish)` is the host-neutral editing contract. A session captures the current instance reference, its revision, and the shared definition's stage objects. **Apply** validates on a cloned instance and calls `publish` only for an actual change; the owner must atomically replace its instance and mark the owning song object/revision if applicable. Another editor's copy-on-write replacement, an in-place instance mutation, or a change to the stage definitions makes the draft stale. The editor then preserves all unsaved values and refuses Apply until explicit **Reload**. Switching stages is similarly blocked while a draft is dirty. An owning UI can call `NotifyConfigurationChanged` to refresh a clean editor or display a conflict while preserving a dirty one. The editor never assumes that unowned Filter instances are SongObjects, nor does it silently modify `SongDocument`.

The editor is deliberately **not yet mounted on an Instrument/FM/note/output field**: none of those objects owns a reusable Filter instance today. The dedicated later integration milestones will add persistent owner fields and bind their copy-on-write publication to this reusable control, including explicit document/audio revision handling. Do not invent a global shared instance or add a fake Filter-use object merely to expose the editor early. The current instance editor does **not** introduce DSP histories or audio processing by itself.

Regression tests: `FilterInstanceOverrideReplacementTests` (Core), `FilterInstanceEditSessionTests` (owner-neutral copy-on-write), and `FilterInstanceEditorControlTests` (headless Avalonia inherited/overridden values, structural choices, atomic combined bands, stage-switch and stale-draft protection).

## Implemented streaming render foundation (explicit bypass)

`Heresy.Render.Filters.StreamingFilterChain` introduces a reusable **per-invocation** incremental engine, independent of the existing tracker-compatible `ResonantFilterState` and speaker-output filters. `FilterChain` (Core) is the immutable-by-use authoring configuration; each `StreamingFilterChain` (Render) is one separately owned set of mutable DSP histories, with one independent processor state **per stage and output channel**. The engine processes individual `Span<float>` frames or interleaved PCM spans, in inner-to-outer layer and stage order. It neither allocates nor prepares coefficients inside the sample loop. Multiple invocations never implicitly share a runtime, including private mixdown hosts.

Preparation resolves effective stage parameters from the configured definition/overrides into independent `PreparedFilterStage` snapshots, including definition ObjectId, layer/stage ordinal, stable stage ID, kind, type generation, all canonical parameter values and a structural-parameter signature. `IStreamingFilterStageFactory.Prepare` can validate sample-rate/Nyquist constraints and precompute per-kind immutable plans; `IStreamingFilterStagePlan.CreateState` produces a separate channel history; `IStreamingFilterStageState.Process/Clone/Reconfigure` forms the incremental stateful DSP contract. The foundation initially shipped the explicit `BypassFilterStageFactory` to pass all 21 selected kinds through unchanged. The following One-Pole milestone adds the `BuiltInFilterStageFactory` as the **default** streaming factory: One-Pole stages now execute real DSP, while all other kinds still use explicit identity/bypass processors until their respective algorithms are implemented. Callers can still select `BypassFilterStageFactory.Instance` for identity testing. The streaming engine is not yet connected to FM/Instrument/voice/channel/output hosts.

`Configure(FilterChain)` prepares the **entire** proposed serial chain before making it visible. Unchanged stages retain state. Nonstructural numeric parameter edits clone and reconfigure existing histories; type/generation changes, structural-choice/number changes, serial reorder/topology changes, or different stage identities build fresh histories. All mutations occur on unpublished copies; if a plan or state configuration throws, the original chain remains operational without a partially applied transition. The channel count and sample rate are fixed for a runtime; a device-format change constructs a new runtime. Once `FinishInput` has been called, reset before reconfiguring or accepting new source frames. This avoids accidental reconstruction of finalized tails.

`Reset()` creates fresh histories for deterministic replay from the start; callers reconstruct a backward seek by replaying earlier input and configuration events in chronological order, **not** by seeking mutable state blindly or building an event journal. `Fork()` deep-copies the existing per-channel histories when a later NNA-host displacement or another explicit state fork needs an independent continuation. The runtime's bounded tail policy is opt-in: a host calls `FinishInput()`, then `RenderTail(destination)`, which feeds zeros through the processors for at most the **sum of serial plans' nonnegative `TailFrames`** and caps it at `maximumTailSeconds` (10 seconds by default). Any unconsumed destination frames are exactly zeroed; render returns the actual number of DSP frames advanced. This is a hard maximum, **not** a claim that an IIR response falls below a particular acoustic threshold. Per-algorithm silence thresholds, denormal safety, and accurate tail estimates are supplied by individual DSP implementations as they land; the One-Pole policy is documented below. An active or infinite script is never automatically deemed ended.

Regression coverage: `StreamingFilterChainTests` checks exact bypass, invalid PCM shape, independent stereo/invocation histories, serial stage/layer order, whole-block vs partitioned PCM, numeric-change history retention, structural resets, stage rename/reorder changes, atomic failures during plan preparation and state reconfiguration, deterministic reset/replay, deep-fork isolation and finite tail draining. Stateful behavior is verified with a **test-only feedback processor**, not misrepresented as a shipped One-Pole implementation. No persistence migration is required because this runtime state is never serialized.

## Implemented One-Pole low-pass / high-pass DSP (6 dB/octave)

`Heresy.Render.Filters.OnePoleFilterStageFactory` implements the first audible filter algorithm for the streaming runtime. Its stage type is `FilterKind.OnePole` with the existing two descriptors: numeric **CutoffHz** (schema 1–20,000 Hz) and structural **Mode** (`LowPass`/`HighPass`). In addition to descriptor validation, preparation **rejects cutoff at or above Nyquist** for the current positive sample rate. Low/high-pass mode is a configuration-time choice, not a continuously modulatable parameter. `BuiltInFilterStageFactory` selects this processor for One-Pole, the real biquad processor for seven Audio EQ Biquads, the shared TPT SVF processor for four SVF responses, the linear ladder processor for one additional type, the nonlinear saturated ladder processor, first-/second-order All-Pass, the feedback comb processor, all four linear-phase windowed-sinc FIR responses, and a neutral plan for the remaining feedforward comb kind; `StreamingFilterChain` defaults to this built-in dispatcher.

The filter is a first-order **topology-preserving transform (TPT) / bilinear-warped integrator**. Let `g = tan(π * CutoffHz / sampleRate) / (1 + tan(π * CutoffHz / sampleRate))`, `s` be the invocation/channel-local integrator history, and `x` an input sample. Each frame computes `v = g * (x - s)`, `low = s + v`, then commits `s = low + v`. **LowPass** emits `low` and **HighPass** emits `x - low`. For identical initial states and excitation the two responses are complementary; the digital magnitude at `CutoffHz` is approximately −3.0103 dB. The response rolls off at first-order / approximately **6 dB per octave** sufficiently away from the corner and Nyquist. Cutoff, coefficient `g` and tail bound are prepared outside the sample loop. This is deliberately separate from the legacy Impulse Tracker resonant filter, whose coefficients/behavior do not change here.

Changing only `CutoffHz` uses `Reconfigure` and **retains the integrator history**, including across channel/runtime `Fork()`; a structural `Mode` change, type change, or reordered stage is incompatible and starts a fresh history as required by the streaming engine. `Reset()` reconstructs zero-state playback for deterministic seeking and replay. Invalid nonfinite input is treated as zero excitation so it cannot poison the recursive state. Extreme but finite transients are saturated to the representable float PCM range rather than converted into Infinity. Residual integrator and output magnitudes below `1e-20` are flushed to exactly zero, well before float denormals, for finite denormal-safe decay.

This first-order IIR has mathematically asymptotic decay rather than a true finite impulse response. Its prepared `TailFrames` is a **conservative finite budget**: for a unit-normalized excitation, estimate the number of zero-input frames required for the magnitude of the recursive pole `|1 - 2g|` to drop to `1e-20` (−400 dB), plus two frames; handle the zero-pole case explicitly, and saturate any very long estimate to `int.MaxValue`. The streaming engine still caps the **total serial-stage tail** at its caller-specified `maximumTailSeconds` (10 seconds by default). This is an upper work budget, **not** a proof of exact silence for arbitrary unbounded excitation. A concrete owner decides when excitation ends; the engine never invents Note Off or forcibly declares an infinite script finished.

PCM regressions in `OnePoleFilterTests` verify TPT impulse coefficients, step/DC behavior, low/high complementary responses, the −3 dB digital corner, low-/high-frequency attenuation and approximate 6 dB/octave slopes, Nyquist checks, near-Nyquist finite output, compatible-history preservation, structural resets, atomic failure behavior, multichannel block partitioning, state fork and deterministic reset/replay, and bounded denormal-safe draining. `StreamingFilterChainTests` continues to assert exact identity under the **explicit bypass factory**. Minimum/Maximum phase conversion for the four FIR response types is implemented; only the separate feedforward comb remains an algorithm TODO; no production song host is yet connected to this engine.

## Implemented Audio EQ Biquads (all seven types)

`Heresy.Render.Filters.BiquadFilterStageFactory` implements the full **Audio EQ Biquads** catalogue group, not the separate SVF or ladder kinds. The seven selectable `FilterKind` values are **BiquadLowPass**, **BiquadHighPass**, **BiquadLowShelf**, **BiquadHighShelf**, **BiquadPeaking**, **BiquadBandPass**, and **BiquadNotch**. `BuiltInFilterStageFactory` dispatches all seven to this shared processor. Their user-facing descriptors are unchanged: **CutoffHz** for every response; **Q** for low/high-pass, peaking, band-pass and notch; **GainDb** for peaking and shelves; and **ShelfSlope** for shelves. Q adjusts resonance/relative bandwidth; GainDb is a *dB* boost/cut, not a linear amplitude. The band-pass uses the RBJ **constant 0 dB peak gain** convention (not the constant-skirt-gain convention). A peaking gain of 0 dB and both shelves at 0 dB have unity frequency response.

Coefficients follow the normalized **RBJ Audio EQ Cookbook** forms. For `ω=2π CutoffHz / sampleRate`, use `sin(ω)`, `cos(ω)`, `α=sin(ω)/(2Q)` for the Q-based families, and `A=10^(GainDb/40)` with shelving `α=(sin(ω)/2) sqrt((A+1/A)(1/ShelfSlope−1)+2)`. The corresponding second-order low/high-pass, shelving, peaking, band-pass and notch numerators and denominators are each normalized by `a0` before rendering. Every coefficient must be finite; the denominator passes the second-order real **Schur stability** conditions `|a2| < 1`, `1+a1+a2 > 0`, `1−a1+a2 > 0`. Preparation rejects cutoff at/above the active Nyquist frequency, and rejects high-gain/high-`ShelfSlope` combinations whose shelving `sqrt` argument is not strictly positive. These constraints are additional to the catalogue's individual numeric ranges; failed preparation never publishes a partly updated chain.

Each prepared immutable biquad plan owns five normalized coefficients and a finite estimated IIR-tail budget. Every invocation/stage/output channel owns an independent **transposed direct-form II** pair of double-precision delay states `z1,z2`. One sample computes `y=b0*x+z1`, followed by `z1=b1*x−a1*y+z2` and `z2=b2*x−a2*y`. All coefficient designs and stability checks occur outside the audio processing loop; a steady processor performs only multiply/add operations per sample. Invalid nonfinite input is treated as silent input, extreme finite outputs saturate to the representable float PCM range, and internal state/output magnitudes below `1e−20` are flushed to exactly zero for denormal-safe tails. The prepared per-stage tail estimate uses the largest stable pole magnitude and a −400 dB unit-impulse decay target with a two-frame allowance. The serial streaming engine still enforces its configured maximum total duration; this is a work bound, not exact mathematical termination of an IIR response.

**History-preserving modulation:** changing a numeric `CutoffHz`, `Q`, `GainDb` or `ShelfSlope` retains `z1,z2` and linearly interpolates the *normalized biquad coefficients* over **32 frames**. Reconfiguration while a transition is in progress starts from the current interpolated coefficient set, not a stale original set. This is a deterministic, per-sample bounded update, with no discontinuous coefficient jump and no requirement to clear a compatible channel's memory. The convex region of stable second-order denominator polynomials ensures interpolation between validated stable coefficient sets remains stable. Stage identity/type/topology changes still reset histories under the streaming engine's existing compatibility contract. An invalid second-stage update does not alter any active first-stage coefficients or histories. `Fork()` copies delay states and any ongoing interpolation; `Reset()` reconstructs an initial state for sample-exact deterministic replay.

`BiquadFilterTests` provides real PCM spectral/impulse tests for **all seven** types, digital cutoff selectivity, approximate 12 dB/octave rolloff, unit band-pass peak, notch center null, Q bandwidth, shelf slope, peaking and shelf ±dB amplitudes, unity at 0 dB, Nyquist and invalid shelf-combination rejection, history preservation and coefficient transitions, repeated rapid modulation, stereo/channel and block-split invariance, independent fork/replay, finite tails, and denormal/nonfinite handling. Existing `OnePoleFilterTests` and explicit bypass tests remain in place. No existing tracker-compatible per-voice or final-speaker filters have been changed; graph/tone/channel integration is a separate milestone.

## Implemented shared topology-preserving SVF (four responses)

`Heresy.Render.Filters.SvfFilterStageFactory` implements all four selectable **State Variable Filter** kinds: `SvfLowPass`, `SvfHighPass`, `SvfBandPass`, and `SvfNotch`. All four use exactly the **same pair of topology-preserving (TPT) integrators**; the response selector chooses the output without introducing a separate biquad state machine. `BuiltInFilterStageFactory` now routes these types to real DSP alongside One-Pole and the seven Audio EQ Biquads, leaving only the other eight kinds on explicit bypass. No changes are made to the older tracker-compatible `ResonantFilterState` or legacy final-speaker filtering.

For valid `CutoffHz` strictly between zero and Nyquist at the active sample rate, and positive `Q`, preparation computes `g = tan(π CutoffHz / sampleRate)`, `k = 1/Q`, and coefficients `a1 = 1/(1 + g(g+k))`, `a2 = g*a1`, `a3 = g*a2`. With histories `ic1`, `ic2`, a sample `x` computes `v3=x-ic2`, `v1=a1*ic1+a2*v3`, `low=ic2+a2*ic1+a3*v3`, and `high=x-k*v1-low`, then updates the two integrator memories to `ic1=2*v1-ic1` and `ic2=2*low-ic2`. The four emitted responses are `low`, `high`, `k*v1` (band-pass with **0 dB peak at center**, where Q controls relative bandwidth), and `low+high=x-k*v1` (notch). This also makes `low+high+band=x`, assuming matched initial histories and excitation. Unlike adding separate cascaded filters, all outputs derive from the same physical state equation. Its static transfer functions match the corresponding RBJ biquads at the same frequency/Q, but its TPT integrator topology is more useful for controlled fast modulation.

Preparation rejects invalid sample rates and cutoff values at/above Nyquist, and verifies finite positive `g,k` and stable digital poles. Pole magnitudes yield a conservative **−400 dB unit-impulse** drain estimate plus two frames; the chain's usual maximum-tail duration still caps the rendered zero-input tail. Histories are separate for each stage, output channel, playback invocation and fork, use double-precision integrators, treat nonfinite PCM input as zero excitation, clamp any extreme finite output to representable float PCM, and flush magnitudes below `1e-20` to exact zero to avoid denormals. IIR tails are mathematical asymptotes; the bounded drain remains a CPU/work policy, not proof of silence for unbounded input.

**Modulation/retuning:** Both `CutoffHz` and `Q` are continuously adjustable numeric parameters. A compatible edit keeps `ic1,ic2` unchanged and interpolates the positive topology variables **`g` and `k` over 32 frames**, recalculating `a1,a2,a3` only during that short transition. This preserves the stable TPT form at *every intermediate frame*, unlike arbitrary interpolation of unrelated biquad numerator and denominator sets. A new update partway through an unfinished transition restarts from the current intermediate values; its output remains independent of render block partitioning. A response-kind, stage-generation, identity or ordering change causes a fresh integrator history under the streaming chain's compatibility contract. `Fork()` deep-copies the histories **and** any in-flight interpolation, and `Reset()` permits exact backward-seek reconstruction through deterministic replay. Coefficient preparation does not run in the SDL callback.

`SvfFilterTests` checks each response's impulse, corner/sideband spectral response, a unit-gain band-pass peak and notch zero, Q-dependent resonance and bandwidth, low/high/band summation, corresponding static RBJ biquad equivalence, real sample-rate/Nyquist rejection with atomic no-change on a failed multi-stage update, history-preserving cutoff/Q changes, thousands of fast stereo retunes (including low frequency, near-Nyquist, low-Q and high-Q extremes), block partition invariance, fork/replay isolation, incompatible-kind reset, denormal/nonfinite safety, and bounded zero-input tails. DSP is implemented in the reusable engine but **is not connected to an Instrument/FM/note/channel/output host yet**.

## Implemented linear four-pole ladder (24 dB/octave)

`Heresy.Render.Filters.LinearLadderFilterStageFactory` implements `FilterKind.LadderLinear` as a **linear four-pole low-pass ladder**, distinct from the pending nonlinear/saturated ladder. The existing authored parameters are `CutoffHz` (1–20,000 Hz) and `Resonance` (0–1). Preparation additionally rejects a cutoff at or above Nyquist for the active positive sample rate and any nonfinite or out-of-range parameters. The built-in dispatcher selects the real linear-ladder processor for `LadderLinear` only; `LadderSaturated` is implemented separately by the nonlinear factory described below. No changes are made to legacy Impulse Tracker resonant filters or speaker-output filters.

The linear ladder uses **four cascaded bilinear/TPT one-pole integrators**, each with its own double-precision memory `s1…s4`. Let `g=tan(π*CutoffHz/sampleRate)`, `G=g/(1+g)`, and `K=3.8*Resonance`. Each section produces `yi=G*xi+(1−G)*si`, then updates `si=2*yi−si`; the first stage receives `x−K*y4`, forming negative feedback from the final stage. Importantly, **the feedback is solved algebraically per frame**, not delayed by one sample or iterated: `y4=(G^4*x + (1−G)(G^3*s1+G^2*s2+G*s3+s4))/(1+K*G^4)`. This gives a consistent zero-delay feedback solution, processing all four stages with a fixed number of arithmetic operations per frame. There is no nonlinear drive, clipping inside the feedback path, or oversampling: those are deliberate boundaries between the linear and saturated ladder types.

**Resonance stability contract:** the continuous prototype has characteristic equation `(1+s/ω)^4+K=0`. The analog stability boundary is `K=4`, where one pole pair becomes marginal. We map the allowed maximum authored resonance `1` to `K=3.8`, strictly below that threshold. Under the bilinear transform, the left-half-plane poles remain strictly inside the digital unit circle for all accepted sample rates/cutoffs. Even maximum resonance is therefore **decaying**, not a persistent synthesizer oscillator; its response can have a pronounced resonant peak near cutoff, but does not run away for bounded inputs. The classic unnormalized negative-feedback topology reduces the DC gain to `1/(1+K)`; this is intentional, **not** an automatic DC-gain-compensated EQ. With `Resonance=0`, the response matches four independent One-Pole low-pass stages at identical cutoff, has unity DC gain, and rolls off at approximately **24 dB/octave** away from its corner and Nyquist (with additional digital warping near Nyquist).

**Transitions and ownership:** `CutoffHz` and `Resonance` are nonstructural numeric parameters; an edit retains all four per-invocation, per-stage, per-output-channel histories. The positive TPT `g` and bounded feedback `K` are linearly interpolated over **32 output frames**, including mid-transition retuning. Every intermediate pair remains within the provably stable region. Reconfiguring a stage is atomic across the serial streaming chain; if preparation of a later stage fails, none of the earlier histories or coefficients are published. `Fork()` independently clones all four memories and ongoing interpolation; `Reset()` restarts the same prepared configuration at zero state. A backward seek reconstructs state by replaying the original input/parameter timeline; sample/block partitioning does not change results.

The factory analytically computes the digital pole-radius bound from the four analog roots and the TPT/bilinear mapping. Its estimated zero-input tail uses a −400 dB unit-excitation decay target with additional allowance for fourth-order polynomial terms, capped by the engine's `maximumTailSeconds`. This is a **finite CPU/work bound**, not an exact endpoint for an IIR impulse response or a guarantee of silence for arbitrary infinite excitation. Processing suppresses invalid nonfinite input, clamps extreme finite output to float PCM range, and flushes internal histories and output below `1e−20` to exact zero, avoiding denormals. The processing loop performs no allocations or trigonometric/coefficient preparation.

`LinearLadderFilterTests` covers equivalence to four cascaded One-Pole stages at zero resonance, spectral four-pole rolloff and DC gain, enhanced resonant peak with strict self-oscillation avoidance at maximum resonance, Nyquist validation, atomic failure of multi-layer reconfiguration, compatible history retention and smooth parameter updates, aggressive changing cutoff/resonance across stereo PCM block partitions, independent forks/in-flight transitions and deterministic replay, finite tails and numerical safety. It deliberately does not claim to implement the separate nonlinear/oversampled ladder or to integrate Filter chains into song hosts yet.

## Implemented nonlinear/saturated four-pole ladder

`Heresy.Render.Filters.SaturatedLadderFilterStageFactory` implements **`FilterKind.LadderSaturated`** as a *distinct algorithm*, without changing the linear ladder or any legacy tracker-compatible filter. Existing descriptors supply `CutoffHz` (1–20,000 Hz), `Resonance` (0–1), `Drive` (0.1–10), and the **structural** enumerated `Oversampling` (1x/2x/4x, default 2x). Cutoff must be strictly below the **host** sample rate's Nyquist even when internally oversampled, so the authoring meaning remains consistent. Nonfinite/out-of-range values or unsupported structural choices are rejected during preparation before any live chain is modified.

**Nonlinear topology:** Four cascaded TPT one-pole integrators remain linear; an implicit, zero-delay, **tanh-saturated input/feedback junction** makes the feedback loop nonlinear. This is not an emulation that applies clipping *after* an ordinary linear ladder, nor a claim to model transistor-by-transistor/per-pole saturations. Each oversampled instant solves `y4 = M + G^4 * tanh(Drive*(x−K*y4))/Drive`, where `g=tan(π*CutoffHz/internalSampleRate)`, `G=g/(1+g)`, `K=3.8*Resonance`, and `M=(1−G)*(G^3*s1+G^2*s2+G*s3+s4)` contains the four stage histories. The driven input is then `tanh(Drive*(x−K*y4))/Drive`; each TPT integrator advances once, with `si' = 2*yi−si`. Since `tanh` is monotone with derivative between 0 and 1, the algebraic equation has **one root**, with derivative of its residual at least 1. The processor uses **at most 12 bounded Newton/bisection root iterations** per internal sample. It never inserts a one-sample feedback delay, iterates indefinitely, or allocates memory within the PCM loop. `tanh(Drive*z)/Drive` gives unity slope near zero (preserving small-signal behavior) while increasing Drive lowers the large-signal saturation threshold. The saturation is *inside* the feedback loop and creates harmonics even without a dedicated distortion effect.

**Resonance and stability:** As with the linear ladder, `Resonance=1` maps to `K=3.8`, strictly below the linear four-pole self-oscillation threshold `K=4`. Because the saturating junction cannot increase its small-signal slope above unity, its feedback cannot become more aggressive than this stable linearized case. Preparation computes/validates the worst-case digital pole radius using the corresponding bilinear mapping. Resonance therefore strengthens the spectral peak without creating unbounded self-oscillation on ordinary bounded input. Finite input and output are guarded; NaN/Infinity excitation is replaced with zero and sub-`1e−20` integrator/output values are flushed, while output exceeding float PCM range is saturated to finite representable values.

**Actual, bounded oversampling:** `1x`, `2x`, and `4x` run exactly 1/2/4 implicit-solver and four-pole DSP substeps per output frame. A one-frame-history **piecewise-linear interpolator** creates the intermediate excitations; when the factor exceeds 1, **four additional TPT low-pass reconstruction sections**, tuned to 0.42 times the base sample rate and evaluated at the internal rate, suppress out-of-band distortion products before returning the last substep's output to the host rate. This is a finite-order anti-alias approximation, **not** a perfectly band-limited converter or zero-latency, sample-identical substitution for 1x; the reconstruction filter contributes phase/group delay and changes sound and CPU cost. Each output channel/invocation owns its independent four main memories, four reconstruction memories, previous input, and ramp state. Preparation caps internal sample-rate multiplication to the supported integer range; factor is never inferred from an unbounded dynamic value.

**State changes and tails:** `CutoffHz`, `Resonance`, and `Drive` are continuous numeric controls, interpolated together over **32 host output frames**, spread across the substeps. Compatible updates preserve all four integrators, reconstruction memories, and previous excitation; a repeated edit during an unfinished ramp starts from the current interpolated values. `Oversampling` is structural: changing 1x/2x/4x replaces the state entirely, including interpolation and anti-alias history. The streaming engine continues to validate/publish entire chains atomically; `Fork()` deep-copies all histories and pending ramps, and deterministic seek uses `Reset()` plus playback of the original parameter/input timeline. Nonlinear IIR decay remains theoretically asymptotic. A conservative fourth-order, linearized **−400 dB unit-excitation** decay budget is converted to output frames, with additional reconstruction-filter allowance, then capped by the streaming invocation's maximum tail seconds. This is a **bounded work policy**, not a mathematical guarantee that an arbitrarily loud/infinite source has become silent.

`SaturatedLadderFilterTests` verifies audible distortion versus the linear ladder, Drive-dependent saturation and low-level response, all three oversampling choices, reduced harmonic-alias energy under 4x reconstruction, base-rate Nyquist validation, atomic multi-layer failure, history-preserving numeric retuning and structural oversampling reset, rapid modulation with bit-identical chunk partitioning, three-channel fork/replay continuity, full-scale and invalid PCM protection at maximum resonance, and finite capped denormal-safe tails. The main DSP code is in `Heresy.Render` and still **has no production song host binding**; FM nodes, Instruments, note events, channels, and final outputs remain separate integration tasks.

## Implemented All-Pass phase shifting (order 1 or 2)

`Heresy.Render.Filters.AllPassFilterStageFactory` implements **`FilterKind.AllPass`**, now dispatched through the normal `BuiltInFilterStageFactory`. Its existing descriptors are the continuous numeric `CutoffHz` (1–20,000 Hz by catalogue; preparation also requires strictly below the active sample rate's Nyquist) and structural choice `Order` ("1" or "2", default "1"). `CutoffHz` represents the **phase-center frequency**, not a −3 dB amplitude cutoff. This stage changes phase while retaining exactly unity **steady-state magnitude at all digital frequencies**; it does not suppress or amplify any frequency in the ideal steady state. Finite startup, automation and reset transients need not have perfectly constant instantaneous energy.

A first-order section uses the rational transfer function `H(z)=(a+z⁻¹)/(1+a z⁻¹)`, with `t=tan(π*CutoffHz/sampleRate)`, `a=(t−1)/(t+1)`, and `−1 < a < 1`. For input `x` and state `s`, each PCM frame computes `y=a*x+s` followed by `s'=x−a*y`. Its digital pole is `−a` and its zero is `−1/a` (infinity for a zero coefficient); the all-pass zero/pole reciprocal relation guarantees `|H(e^{jω})|=1`. At the authored center frequency its phase is **−π/2 (−90°)**, moving continuously from 0° near DC to −180° near Nyquist. `Order=2` is a **cascade of two identical first-order sections** with separate memories and the same coefficient, giving the squared transfer function, unity magnitude and **−π (−180°) at center** (−360° total rotation through Nyquist, understood modulo 2π). No undocumented resonance/Q or bandwidth parameter is introduced.

`Prepare` validates the sample rate, Nyquist constraint, structural Order and finiteness/stability of the coefficient *before* publishing a processing plan. All coefficients are designed outside the render loop. Runtime state contains one or two double-precision recursive delay values; every invocation and output channel has independent state. An incompatible structural `Order` update replaces the state, while an ordinary cutoff edit **retains the histories** and linearly interpolates the stable coefficient `a` over **32 frames**, starting from the current intermediate value if retuned again during the ramp. The entire path remains stable because any convex interpolation of two coefficients strictly inside `(−1,1)` stays inside that interval. Streaming chunk boundaries do not change the numeric trajectory. `Fork()` deep-copies the histories and an in-progress ramp; `Reset()` establishes zero-state playback, with earlier parameter events replayed to reconstruct seeks.

Invalid nonfinite PCM input is treated as silence before recursion; extreme output amplitudes are saturated to the representable float range rather than allowed to poison downstream stages. Values below `1e−20` in recursive memories or outputs are flushed to exact zero to avoid denormals. As for all recursive filters, the mathematical impulse response is infinite; each section's **pole radius `|a|`** gives a finite conservative −400 dB unit-amplitude decay budget, with an additional repeated-pole polynomial allowance in Order=2. The engine's `maximumTailSeconds` enforces the final hard work bound; this is not proof of silence for arbitrary unbounded excitation.

`AllPassFilterTests` verifies exact first-/second-order impulse recurrences, steady-state unit magnitude at multiple frequencies, analytically specified phase curves and −90°/−180° rotation at cutoff, order changes and resets, smooth cutoff changes without dropping history, strict Nyquist checks and atomic failure of a later stage, rapid repeated retuning and stereo block partition identity, three-channel independent `Fork` and deterministic replay, and finite denormal-safe zero-input tails. An explicit bypass regression remains on a not-yet-implemented FIR kind. This completes the one selectable all-pass kind; the five remaining catalogue kinds are **CombFeedforward** and the four standard FIR responses (feedback comb is now an implemented IIR). Audio host wiring remains a separate milestone; existing legacy/tracker filters are unchanged.

## Implemented feedback comb (IIR) with discrete echo delay

`Heresy.Render.Filters.FeedbackCombFilterStageFactory` implements the selectable **`FilterKind.CombFeedback`** as an independent, stable, incrementally rendered feedback-delay IIR. The existing shared catalogue specifies **`DelaySeconds`** as a **structural** numeric parameter (0.001–2 seconds, default 0.02), **`Feedback`** as a continuous numeric parameter (−0.95 to +0.95, default 0.5), and **`Mix`** as a continuous wet/dry blend (0–1, default 0.5). The factory makes no modifications to the older tracker-compatible voice filters or to the separate *feedforward* FIR comb.

**Signal contract:** The per-channel delay ring stores `w[n] = x[n] + Feedback*w[n−D]`; the **wet output** is the *delayed tap* `w[n−D]` and the final output is `y[n] = (1−Mix)*x[n] + Mix*w[n−D]`. With an impulse at frame zero and steady parameters, the immediate output is `1−Mix`, followed by a wet echo of `Mix` at frame `D`, `Mix*Feedback` at `2D`, then `Mix*Feedback²` at `3D`, etc. Negative feedback alternates echo polarity. `Feedback=0` still produces **one audible delay** when Mix is nonzero, while `Mix=0` routes exact dry audio and has no audible tail. This intentional wet-tap convention is distinct from treating `x+Feedback*w[n−D]` as the wet signal (which would make Mix meaningless at zero feedback). The normalized full-wet frequency response is `H(e^{jω}) = e^{−jωD}/(1−Feedback*e^{−jωD})`; positive feedback emphasizes harmonics of the delay fundamental, negative feedback swaps peaks and dips at alternating half periods. No amplitude normalization is applied to hide resonance gain.

**Discrete delay and memory limit:** Preparation converts seconds to an integral number of output frames using `Round(DelaySeconds*sampleRate, MidpointRounding.AwayFromZero)`; this produces a minimum delay of one frame. The choice is deterministic across block sizes and platforms, with no fractional-delay interpolation or implicit sample-rate conversion. A stage/channel is limited to **1,000,000 double-precision delay samples (8 MB)**. Configurations requiring a longer delay at the chosen sample rate are rejected before publication even if `DelaySeconds` itself is within its authored 2-second range. The runtime owns one private `double[]` circular buffer and its read/write position **per invocation, serial stage and output channel**. Preparation, state construction and deep cloning allocate as needed, but **processing each frame performs constant-time operations with no buffer allocation**; it never creates an entire-song delay history. Different stereo speakers, sibling notes, or mixdowns never implicitly share the echo ring.

**Safe modulation and structural edits:** `Feedback` is bounded strictly inside the unit circle so the impulse response geometrically decays rather than self-oscillating; the bound is enforced in the catalogue *and* DSP preparation. `Mix` and `Feedback` can be changed together while retaining the entire ring and write position; their real-time numeric values interpolate over **32 output frames**, including when a new update interrupts an unfinished ramp. Intermediate feedback stays within `[−0.95,+0.95]` and Mix within `[0,1]`. **Changing `DelaySeconds` is structural** and starts a new, empty delay ring, even if two different authored second values round to the same sample count; old echoes are not silently remapped into a different delay topology. The parent streaming engine prepares/reconfigures the entire proposed chain atomically, so an invalid second filter cannot partially change the first. `Fork()` deep-copies ring contents, position and any in-flight coefficient transition; `Reset()` drops all previous echoes and begins at the new configured starting point. Seeking backward reconstructs a timeline by replaying its earlier input and configuration changes.

**Explicit bounded tail:** For a nonzero wet Mix, even `Feedback=0` requires **exactly `D` trailing frames** to reach the first and only delayed echo when the source ended immediately after an excitation. For nonzero feedback, the factory estimates the cycles required for a unit-normalized echo to reach **−400 dB** (amplitude `1e−20`) using geometric decay, with a one-cycle allowance; the result is computed using wider numeric arithmetic and saturated to `int.MaxValue` before the containing chain's normal `maximumTailSeconds` cap. `Mix=0` reports zero audible tail. This is a *finite DSP work budget*, not proof of silence after an unbounded source or a promise that a deliberately short user cap includes every echo. Internal delay histories and outputs below `1e−20` are flushed to exact zero to avoid denormals; invalid nonfinite input becomes zero excitation, and extreme finite outputs are clamped to representable float PCM.

`FeedbackCombFilterTests` checks exact dry and wet impulse timing, positive/negative geometric echo polarity, zero-feedback single-delay and zero-mix bypass semantics, deterministic rounding at half-frame boundaries, frequency-response peaks/notches for both feedback signs, preservation and smoothing of feedback/mix changes, total reset on structural delay changes, sample-rate-dependent maximum memory rejection with atomic multi-stage rollback, finite capped tails including an echo arriving *at the last budget frame*, rapid retuning with bit-identical block partitioning, independent stereo and invocation histories, three-channel `Fork()`/replay, and numerical/denormal safety. This processor is routed through `BuiltInFilterStageFactory`; the four standard FIR kinds now implement linear-phase DSP, and the feedforward comb now executes its own two-tap FIR. Integration with real FM, Instrument, note/channel or final speaker hosts remains a separate TODO.

## Implemented feedforward comb (FIR) with a single delayed tap

`Heresy.Render.Filters.FeedforwardCombFilterStageFactory` implements **CombFeedforward** independently of the feedback IIR processor. Its two-tap transfer is **`y[n] = x[n] + Mix*Feedforward*x[n−D]`**, equivalently a wet signal `x[n] + Feedforward*x[n−D]` blended with the unmodified dry input. `Feedforward` is continuous in **[−1,+1]** (default +0.5), `Mix` is continuous in **[0,1]** (default 0.5), and structural `DelaySeconds` is **0.001–2 seconds** (default 0.02). For an impulse the immediate dry tap is always 1, the sole possible delayed tap at D is `Mix*Feedforward`, and there are **no recirculated echoes**. Mix=0 or Feedforward=0 is neutral; negative feedforward reverses the echo polarity. The feedback comb has a *different* wet-tap convention (`(1−Mix)*x + Mix*w[n−D]`) and recursively stores its prior wet signal; the two kinds are not aliases.

The complex transfer is `H(e^{jω}) = 1 + a*e^{−jωD}`, `a=Mix*Feedforward`. For positive a, delay harmonics have magnitude `1+a` and alternating half-periods have magnitude `|1−a|`; negative a interchanges those locations. At `|a|=1`, there are periodic true spectral nulls. Phase is generally **frequency-dependent**, so the stage reports no fixed group-delay metadata; `PreparedLatencyFrames=0` is not zero acoustic latency. There is no automatic dry-branch compensation. Only original input, never filter output, enters its ring.

`D = Round(DelaySeconds*sampleRate, AwayFromZero)` produces at least one sample. Prepared delays beyond **1,000,000 frames/channel** (8 MB of doubles) reject before publication, even if authored seconds pass schema validation. Each invocation/stage/output channel owns a private D-element circular ring processed in O(1) with no per-frame allocations. Nonfinite PCM is sanitized to zero; tiny samples/outputs flush to zero to avoid denormals, and outputs saturate at finite float extremes. Structural delay changes replace history even when different authored seconds quantize to the same D. Feedforward/Mix edits preserve the ring and cursor, smoothing each value over **32 output frames**. A mid-ramp edit starts from currently effective values. Entire-chain configuration remains atomic; `Fork()` copies ring, position and unfinished gain ramps; `Reset()` and chronological replay are deterministic.

`TailFrames = D` is the exact worst-case finite upper bound for this two-tap FIR. An echo from excitation immediately before `FinishInput()` may reach the very last budget frame. The plan also advertises D when target gains are neutral: in-flight gain transitions may not yet be silent, and a zero announced tail could discard that output. This is a conservative bounded work allowance, not a claim that a neutral steady-state stage audibly rings. The containing chain still enforces its `maximumTailSeconds` cap, which can intentionally truncate a longer delayed echo. No IIR decay estimate applies.

## Implemented standard windowed-sinc FIR: four response types, three phase modes

`Heresy.Render.Filters.LinearPhaseFirFilterStageFactory` implements **`FirLowPass`**, **`FirHighPass`**, **`FirBandPass`**, and **`FirNotch`**. Its sample-rate-specific `Prepare` generates a **fixed-length odd-tap Type-I symmetric FIR** for one of the three catalogue windows: **Hann, Hamming, Blackman**. `TapCount` is an exact structural integer length of **3–2047 odd taps**. `TransitionWidthHz` is the structural 1–5000 Hz design *target*; there is no false guarantee of a particular stopband attenuation from an insufficient tap count or a poor window. `Window`, `TapCount`, `TransitionWidthHz`, and `PhaseResponse` are structural, while frequency/band-edge numeric parameters are compatible, continuously configurable parameters. `PhaseResponse` accepts **Linear**, **Minimum**, or **Maximum**. All three execute real DSP; the linear-phase windowed-sinc design supplies the common reference magnitude before configuration-time phase conversion.

**Frequency and transition semantics:** all authoring frequencies are measured in **Hz** and must be strictly between zero and the current render sample rate's Nyquist. `CutoffHz` represents the **nominal edge of the passband**. `LowCutoffHz` and `HighCutoffHz` represent the nominal edges of a band-pass's passband or a notch's rejection band. The ideal sinc cutoff is the *midpoint of the transition*, displaced by **half `TransitionWidthHz` away from that authored pass/reject band**. Thus low-pass uses ideal frequency `fc=CutoffHz + Width/2`; high-pass uses `fc=CutoffHz − Width/2`; band-pass uses `lo=LowCutoffHz − Width/2`, `hi=HighCutoffHz + Width/2`; and notch uses `lo=LowCutoffHz + Width/2`, `hi=HighCutoffHz − Width/2`. The last case requires an authored rejection band **strictly wider** than the requested transition width. Any shifted ideal edge at/beyond DC or Nyquist, reversed/overlapping band edges, nonfinite values, or an impossible-to-resolve near-zero passband is **rejected during preparation**, before any active state is published. This convention makes Width a *meaningful shape parameter*, not an ignored UI field; actual spectral steepness still depends on the selected window and available taps.

**Coefficient generation:** with `M=(TapCount−1)/2`, offset `k=i−M`, and sample rate `Fs`, define `L(fc,k)=2fc/Fs` for `k=0`, or `sin(2πfc k/Fs)/(πk)` otherwise. The ideal impulses are `L(lo,k)` for low-pass, `δ[k]−L(lo,k)` for high-pass, `L(hi,k)−L(lo,k)` for band-pass, and `δ[k]−L(hi,k)+L(lo,k)` for notch. Multiply by the selected symmetric Hann/Hamming/Blackman taper. Normalize the resulting finite coefficients for **unity reference passband response**, using DC for low-pass/notch, Nyquist for high-pass, and the midpoint of the intended band for band-pass. A near-zero or nonfinite normalization is rejected instead of producing an uncontrolled gain. The reference Linear coefficients are symmetric to floating precision and have **exact integer group delay `M` frames** in their passbands (except near a response sign/zero where phase is undefined). Minimum/Maximum coefficients are not symmetric and have **frequency-dependent group delay**. This delay and the output ring's exact finite impulse tail `TapCount−1` frames are completely separate quantities.

**Latency reporting and DSP state:** `ILatencyAwareFilterStagePlan` exposes fixed group-delay metadata when it is mathematically defined: **`M` for Linear phase**, and **0 (no reportable constant group delay)** for Minimum/Maximum. `StreamingFilterChain.PreparedLatencyFrames` atomically sums reported fixed delays for serial stages, including forked states and subsequent reconfiguration. **Zero for nonlinear-phase FIR does not imply zero acoustic latency or zero group delay at every frequency.** This is *reported metadata*, **not automatic dry-path compensation**: hosts combining parallel dry/filtered channels must align them in a later integration step. Each actual invocation/stage/output channel owns its own `double[]` circular PCM history, one sample per authored tap, plus the current write cursor. Steady per-frame convolution uses **O(TapCount)** deterministic multiply/add operations and **no PCM-loop allocations**; configuration can allocate coefficients and the history array outside the loop. The result is saturated to the finite float PCM range and values below `1e−20` are flushed to exact zero. NaN/Infinity excitation becomes zero so a malformed signal cannot contaminate the ring.

**Configuration changes:** because `CutoffHz` and the two band-edge frequencies are not structural, compatible numeric updates **retain the existing circular PCM history and read/write position**. The prepared coefficient arrays interpolate across **32 output frames**; for Linear mode this maintains Type-I symmetry. For Minimum/Maximum modes the interpolated coefficients may have a transitional phase response which is not itself exactly minimum/maximum phase, but each endpoint is a properly prepared design. Reconfiguration during an unfinished ramp starts from its *current* coefficients. All coefficient generation and any mid-ramp vector materialization happen **before** the runtime publishes the new state, not per sample. Changes to `TapCount`, `Window`, `TransitionWidthHz`, `PhaseResponse`, stage identity, or stage ordering replace histories under the shared structural contract; no orphaned pre-change delay samples can leak out. Bad cutoff/phase/window configurations are **atomic failures** across all stages. `Fork()` deep-copies the delay ring, cursor and in-flight transition, while `Reset()` and chronological replay reconstruct deterministic seeking. Output chunk partitioning has no effect on processing results.

**Finite tail and resource policy:** a length-`N` FIR produces exactly **at most `N−1` trailing PCM samples after the last excitation** (and some windows have zero-valued extreme taps). `TailFrames=N−1` is exact as a mathematical upper bound, not a geometric IIR decay estimate. The streaming engine adds serial-stage FIR tails and clamps to the caller's `maximumTailSeconds` budget. If that limit is shorter than the true convolution tail, the **explicit caller cap truncates** the audio; no hidden infinite draining occurs. The maximum one-stage processing budget is fixed at 2047 multiplications per output sample plus loop overhead per channel; unlike the IIR families this is deliberately a comparatively expensive CPU effect. There is no per-frame FFT allocation, no sample-rate-independent absolute delay, and no promise that the given arbitrary TapCount can achieve the requested transition width.

`LinearPhaseFirFilterTests` verifies symmetric exact finite impulses and configurable window coefficients for all four responses; passband and rejection-band spectra; measured complex phase and known group delay; visible TransitionWidthHz influence; Nyquist/band-edge/insufficient-tap rejection; real Minimum/Maximum preparation; history-preserving numeric transitions vs structural tap/window/width resets; multi-layer atomic preparation failure; serial latency/tail accounting; stereo chunk invariance under repeated modulation; independent three-channel forks and reset/replay; bounded finite tails and nonfinite-input safety; and the maximum 2047-tap limit. All 21 selectable filter kinds now have real DSP. All three standard FIR phase modes are implemented. This reusable engine is not yet integrated into live song hosts.

## Implemented Minimum- and Maximum-phase standard FIR conversion

`Heresy.Render.Filters.FirPhaseConversion` now turns the existing windowed-sinc **Linear** coefficient vector into **Minimum** or **Maximum** phase without changing `TapCount`, window, cutoffs, or the finite FIR streaming processor. The Linear design is the **common reference magnitude** for all phase choices. Conversion is performed strictly in `LinearPhaseFirFilterStageFactory.Prepare`, never inside the PCM loop. The `PhaseResponse` field remains structural and a change among Linear/Minimum/Maximum resets the entire stage history at its scheduled frame, even though the resulting convolution rings have the same length.

**Real-cepstral minimum-phase conversion:** Zero-pad the real linear coefficients to the next power of two of at least **32×TapCount**, with a minimum of 4096 complex samples and a maximum of 65,536 at the catalogue's 2047-tap ceiling. Run a deterministic iterative radix-2 FFT; take the **log spectral magnitude**, flooring exact/near zeros at the greater of `1e−12` absolute or `1e−12` times the largest spectrum magnitude. Inverse FFT produces a real cepstrum. Retain its DC and Nyquist terms, **double strictly positive quefrencies**, discard negative quefrencies, and FFT that causal cepstrum to obtain the complex logarithmic spectrum. Complex-exponentiate, inverse FFT, and **truncate the causal impulse to the authored N taps**. Normalize the truncated sequence at the same reference passband frequency used for the Linear coefficient design (DC low-pass/notch, Nyquist high-pass, central band-pass), rejecting nonfinite or unresolved passband amplitudes. The result is an **approximate finite-length minimum-phase spectral factor**, not a claim of exact root reflection of every high-order unit-circle zero. Windowing, spectral flooring, cepstral wraparound and finite truncation introduce small bounded magnitude deviations versus the symmetric reference. The tests verify these deviations directly rather than asserting bit-identical spectra. Near exact notch zeros, phase is undefined and relative spectral-error measures are not meaningful.

**Maximum phase is the exact time reversal** of those minimum-phase taps. This preserves the same finite-length magnitude *by construction*, while concentrating impulse energy toward the **end** of the delay window; minimum phase concentrates energy toward its **start**, with substantially reduced energy-centroid delay compared with Linear. Both are real finite-length FIRs, use the existing per-channel circular histories, and produce no samples beyond the N−1-frame tail (subject to normal explicit `maximumTailSeconds` truncation). Their phase and group delay vary with frequency. Therefore, `PreparedLatencyFrames` continues to report `(N−1)/2` for **Linear**, and reports **0 fixed/known linear group-delay frames** for Minimum and Maximum. This **is not a claim that these filters have zero actual latency or frequency-independent phase**; future hosts must model alignment or measure effective delay according to use.

**Resource and transition contract:** The bounded FFT and new coefficient arrays are created only when preparing a configuration or a compatible numeric frequency redesign; actual sample processing remains the same O(N), allocation-free FIR convolution. The phase choice is a **structural** parameter with no audio-rate modulation port. Cutoff/band-edge numeric changes still preserve private per-invocation/channel delay rings, smoothing the newly prepared coefficient vector across **32 output frames**; interpolation is deterministic across block sizes and may be temporarily neither strictly minimum nor maximum phase between endpoints. Forking copies the ring and any in-flight smoothing, reset/replay reconstructs earlier configurations, and failed preparation never publishes partial changes to the current chain.

`FirPhaseConversionTests` independently DFT-checks all four FIR response families against the Linear reference and between Minimum/Maximum, validates exact maximum-vs-minimum impulse reversal and energy-centroid ordering, confirms frequency-dependent phase and unchanged reference-band gain, checks atomic structural state replacement, numeric parameter updates, deep stereo fork, fixed-latency reporting, chunk-invariant retuning, the 2047-tap FFT bound, and finite tail behavior. No FM/Instrument/channel production song hosts yet use the reusable filter engine; only the **feedforward comb** remains an unimplemented selectable filter kind.

## Parameter categories and structural changes

**Continuous parameters** can be driven by FM graph inputs and updated through commands; e.g. cutoff, resonance, gain, drive, or modulation-friendly delay, if supported by that algorithm. Recompute coefficients in a bounded, stable manner with suitable smoothing/control-rate optimization. Do not run costly FIR redesign for every frame.

**Structural parameters** are configurable in all parameter editors and command payloads, but have **no FM graph input port**. Examples include FIR tap count, window/design choice, Phase Response, topology/response choices, and other parameters where an audio-rate redesign is inappropriate. Phase Response for standard FIR has **Linear**, **Minimum**, and **Maximum** values. Coefficient preparation for minimum phase and maximum phase occurs only when configuration is constructed or structurally changed. FIR designs are constrained by active sample rate and must have bounded tap/resource limits; define stable behavior for invalid or out-of-range cutoffs.

Changing only coefficients or response output while internal state topology is compatible need not clear DSP histories. A structural change incompatible with previous histories (tap count, topology, delay layout, phase mode where the implementation requires new state, etc.) **implicitly replaces/resets that stage's DSP state at the change's scheduled frame**. All fields and their state transition commit atomically. This may produce a discontinuity; possible future crossfades are not required for v1. Set/clear of an entire Filter object always starts with default/configured values and fresh histories; reselecting the same object is still a fresh selection. Parameter changes to an otherwise selected compatible filter preserve histories.

All assignments must be finite, in validated units. Textual enum values are accepted for structural settings. Structural parameters are not restricted from native parameter-setting commands; such commands may rebuild a stage and swap state atomically.

### Parameter-configuration assistance

Both the instance inspector and the native command editor must offer type-aware guidance/wizard controls derived from the *selected stage's parameter descriptors*: appropriate filter response, frequency/cutoff in Hz, resonance/Q, transition width, FIR taps/window/phase, and compatible option sets. Show estimated cost/latency and range constraints where useful. Entering a user goal such as “low-pass at 2500 Hz” can produce a complete valid parameter set, including mutually dependent structural settings. A helper/assistant must not invent fields unsupported by the stage's selectable type; changing the stage *type* itself remains an edit to the shared Filter definition (or requires selecting a different definition), not an incidental parameter-command side effect.

The same assistance is available for the effect editor and converts its result into editable text, rather than bypassing the validated command model.

## FM graph integration

**FM Filter-node authoring and persistence implemented (11 October 2026):** `FmFilterNode` is a first-class FM graph node with an independent configured Filter use, optional audio Input, one output, optional left-edge numeric modulation inputs, and nonnegative finite `TailSeconds` (default zero). The FM inspector provides `(None)`, italic `New...` creating a shared Filter under the Filters document root, `Edit Definition...` beside the selector, and the embeddable `FilterInstanceEditorControl` for per-use explicit overrides/inherited values. Structural options are editable in the instance editor but do not generate modulation inputs. The graph draws and labels `stageName.parameterName` ports in serial stage order, with height growing to accommodate them. Unconnected audio Input is silent; unconnected modulation ports use per-use static values.

Modulation wiring persists as `FmFilterParameterConnection(StageId, Kind, Generation, ParameterName, SourceNodeId)`, never merely as a displayed input ordinal. Port order is recomputed from the live Filter definition, so stage rename/reorder leaves connections attached to their original parameter. Kind/generation changes and deletions invalidate the previous binding rather than retarget it. Such stale bindings remain identifiable for diagnosis and do not appear as active DAG edges; the graph's existing cycle validator checks all active Filter audio/modulation edges. Editor-only waypoint hints are positional and can be discarded if the corresponding connection moves; they never define the semantic binding.

Version-one FM graph JSON embeds a typed `FilterJson` instance (stable Filter ObjectId, stage IDs, generations and explicit overrides), and persists the node's audio input, signed parameter-source connections and Tail. Shared Filter definitions are decoded before FM graphs, regardless of object enumeration order. Frozen song snapshots deep-copy Filter definitions and their FM uses, while FM synth import includes/remaps only the required shared Filter definitions and preserves all per-use overrides and wire identities. The graph editor applies a copy-on-write instance replacement and marks the song audio revision rather than mutating another use or the shared definition.

**FM streaming DSP and Tail now implemented (11 October 2026):** `FmSynthSound` compiles each reachable FM Filter node into a `FmFilterNodeProcessor` retaining only resolved audio/modulation input indices (dependent nodes always evaluate first). Each `FmSynthSound.CreateState()` invocation maintains its own lazily prepared `StreamingFilterChain` per Filter node, in mono graph-scalar space **before the existing spatializer distributes the output to speakers**. All configured serial stages run through `BuiltInFilterStageFactory`, not the old tracker-compatible resonant-filter path. An unassigned Filter is an identity path; a disconnected audio Input is silent. Playback snapshots freeze the song's shared Filter definitions, while split blocks, replay and backward seeks deterministically reconstruct private histories. A pattern-playback integration test confirms real Filter DSP in the song host.

Optional modulation sources supply **absolute values in each parameter's native units**, not a 0–1 multiplier, and never address structural/choice parameters. Before each incoming sample, a changed, finite set of connected values is checked against descriptors, cross-parameter constraints and current sample-rate-specific DSP preparation. Multiple inputs to the same stage are submitted as one candidate batch; the whole chain is prepared atomically. Invalid or nonfinite modulation preserves the last valid committed parameters and histories, rather than throwing in the audio rendering loop. Stable stage IDs/type generations remain the source of modulation port identities, never display position. Family-specific numeric reconfiguration behavior is preserved: One-Pole changes cutoff immediately, while families with 32-frame transitions continue to interpolate.

At Note Off, the preexisting FM envelope/note analysis establishes the natural exclusive end frame. Finite `TailSeconds` contributes exactly `Ceiling(TailSeconds * sampleRate)` extra frames, using the **maximum** across Filter nodes on the actual audio path to the FM output; a Filter used only as an oscillator/parameter modulation source cannot extend that oscillator's tail. An indefinite envelope stays indefinite. Once this natural boundary is reached, ordinary oscillator, constant and envelope nodes output zero excitation while operators continue combining signals and Filter nodes continue processing *their upstream filtered residuals* with no new ordinary-source input. Serial delay echoes can therefore flow downstream; neither a dry branch nor an ungated oscillator keeps feeding new audio. User Tail remains an intentional budget, **not** the sum of serial physical DSP tails, and can truncate residual output. An authored zero Tail adds no extra lifetime. Overflowing long frame arithmetic saturates the reported end safely.

**Bounded FIR control-side preparation policy (11 October 2026):** For connected numeric ports on any of the four windowed-sinc FIR kinds, the live FM evaluator now captures requests as value structs into a **fixed four-stage latest-wins slot**. No `FilterInstance.Clone`, `StreamingFilterChain.Configure`, windowed-sinc kernel preparation, FFT or phase conversion occurs per PCM sample. Unconnected FIR parameters retain authored values. Before admitting a request, `FirControlPreparationPolicy.TryOffer` validates the full sample's FIR proposal without allocating: immutable stage identity, finite parameter-descriptor limits, sample-rate Nyquist, transition-width-displaced boundaries, strict LowCutoffHz < HighCutoffHz ordering, odd 3–2047 taps and selected phase. A rejected sample cancels stale queued requests. All FIR changes in a mixed IIR/FIR frame are **deferred together**: no non-FIR stage commits while FIR change remains unprepared. Current DSP histories and previously validated FIR coefficients remain untouched, including when overloaded or invalid. This is a deliberately bounded fallback, not silent conversion to a cheaper FIR or a hard claim of exact audio-rate FIR automation.

Control-side callers, never the per-sample loop, may invoke `TryPreparePending` on the captured latest snapshot. Admission caps the *entire* batch at **131,072 deterministic work units** and **2 MiB conservative estimated temporary memory**, with at most **four** FIR stages; linear designs account for 12 units/tap, while minimum/maximum phase additionally charges 16 units per FFT element at the same 4096–65536 transform lengths as `FirPhaseConversion`. The work-unit budget is a hardware-independent complexity proxy, **not an elapsed-time/CPU-cycle guarantee**. Preparation builds separate immutable stage plans and returns the batch only after all stages succeed; failure rejects all and never mutates the active chain. No background thread or automatic scheduler is implied by this API. The independently completed linear-, minimum- and maximum-phase publication milestones now consume admitted immutable plans at explicit control boundaries, preserving convolution history and the 32-frame crossfade. Without a matching admitted candidate the running DSP retains the hold-last-valid response instead of doing coefficient design during PCM. This infrastructure milestone's tests cover deterministic queue bounds, admission/refusal, multi-stage rollback, per-frame allocation, mixed-family fallback and deterministic seeks.

**Linear-phase FIR prepared-kernel publication (11 October 2026):** The four standard FIR responses in `PhaseResponse=Linear` now have a typed, allocation-free candidate publication path that consumes the bounded policy's predesigned plans. `FmSynthSound.PreparePendingFilterControls(RenderContext, SoundState)` is an **explicit caller-controlled, off-PCM control boundary**. **Critical CPU limitation:** The measured GitHub Actions Ubuntu x64 runner could render a single 127-tap nine-stage voice within the 5.333 ms deadline of a 256-frame quantum, but **the one-voice 2047-tap and both four-voice workload profiles missed deadline**. Passing numerical, allocation, determinism, and bounded-work tests is *not* a universal hard-real-time throughput certificate. The dedicated rendering worker/ring-buffer architecture protects the audio-device callback, but it cannot create CPU capacity; host integration must set appropriate voice/effect admission, buffering, or graceful overload strategies with target-machine measurements. Arbitrary 2047-tap FIR voice concurrency must not be claimed safe. The qualification checkbox is closed as a completed **measured assessment with explicit unsuccessful stress profiles**, not an assertion of universal deadline success. Instrument, note-event, host-channel and final-speaker Filter integration milestones remain separately open. Automatic scheduling by a host is **not** introduced: the provided control-boundary API must be called explicitly if FIR modulation is to advance; otherwise FIR remains at hold-last-valid. Host scheduling policies must choose deterministic preparation opportunities independent of arbitrary output `Render` chunking, as documented above.


Add a Filter node with one audio Input, an output, a Filter-object dropdown (including italic New... creating an object in the Filters tree), and **Edit Definition...** beside the selector when nonempty. New... and definition editing follow the shared-object workflow used by graph Envelope nodes. A selected definition projects editable instance controls for every parameter of every stage, named stage.parameter, in serial stage order.

Each continuously modulatable numeric parameter becomes an optional left-edge input port (along with Input), increasing graph node height as needed. Disconnected ports use the instance's configured numerical values; connected ports supply their per-frame values. Structural/enum parameters remain editable but do not become ports. Persist graph connections by stable port identity when practical; adding/removing/renaming a stage must never retarget a connection silently. Do not allow a graph cycle.

Each FM note owns its own filter histories; graph evaluation follows dependency order, including connected parameter inputs evaluated before that Filter node's sample. Split-frame rendering, seek/replay and snapshot isolation must reproduce the same PCM. A filter's output is a normal graph scalar; Input's absence and an unassigned Filter object need a deterministic neutral/bypass behavior and must not crash.

**Tail** is a nonnegative, finite **seconds** property on each FM Filter graph node. It is a manually specified *additional allowance*, not an inferred exact physical impulse-response duration. After the rest of that FM graph has established a finite natural termination boundary (including Note Off and envelope release), add the **maximum Tail of all relevant reachable Filter nodes**, not their sum. An unbounded envelope remains unbounded; Tail cannot manufacture a finite lifetime for it. Continue evaluating filter memory over the extra frames while terminating normal note excitation at the computed base boundary; otherwise an ungated oscillator would keep generating a signal rather than letting a filter tail decay. Stop at the exclusive extended boundary. Serial filters may mathematically require a longer combined decay than max(Tail); the user explicitly controls this budget, so document that limitation, do not silently sum it. Nonexistent/zero Tail adds nothing. Test no-envelope, gated-envelope, frequency-only-envelope, dry-path and multiple-Filter-node cases, plus finite post-release silence.

## Persistent channel filtering, native effects, envelopes and NNA

Every physical/virtual playback channel conceptually has **two distinct filter slots**: a persistent *channel-output* filter and the *current note's* event-local filter (the latter belongs to the current note/voice and naturally migrates with it). Existing Instrument filters are deeper per-note chain layers.

Channel filtering processes the channel's combined voice output, after its note/Instrument filters, before adding to the playback session's speaker mix and before final speaker filters. There is **one channel-output filter per actual host channel**, not one per flattened-scope level. A flattened child event that changes channel filtering acts on the root hosting playback channel; its selection, parameters and envelope bindings **persist after child termination or cancellation**. Scoped channel volume/effect memory continues to behave as before; these filter commands are an intentional exception. A private mixdown creates its own isolated channel filter banks and state, not shared with its parent.

**Persistent channel-output DSP cutover (11 October 2026):** `PlaybackSession` now exposes `ConfigurePhysicalChannelOutputFilter(int host, FilterInstance? use)` and `ConfigureVirtualChannelOutputFilter(uint id, FilterInstance? use, long? scopedOwner = null)`. These are **host setup interfaces**, not the upcoming native command implementation. Preparing a Filter completes before the previous host slot is replaced; null removes the slot. The physical host ID is the real `int` channel number even when multiple recursive Pattern/Sequence owners are currently playing on that host. Virtual host IDs are either an unscoped targeted ID or the tuple `(owner, virtualId)` for invocation-local virtual channels. Stored configurations are cloned and prepared into independent `StreamingFilterChain` histories. Neither a new note nor retirement/cancellation of a child scope resets the host Filter. Each private mixdown already has its own `PlaybackSession` and thus cannot accidentally share a host Filter with the parent's session.

With any such Filter installed, the renderer routes every participating current voice, nested-owner voice and anti-click sample through one bounded temporary **host bus**. That entire post-voice signal is processed exactly once through the host's serial Filter chain, **after** the Instrument and event-local layers plus voice gain and **before** global volume and the final speaker filter bank. A disabled host takes the old direct-to-session summation route, retaining old PCM addition ordering. Processing advances silent frames after source retirement, with each channel Filter's finite maximum tail bound contributing to `PlaybackSession.IsQuiescent`. Native physical and virtual channel Filter selection and typed parameter-update commands are now implemented; their dedicated UI/multiline assignment assistant is still upcoming. Nothing silently assigns channel Filters when opening existing songs.

**NNA fork invariant:** On Continue/Off/Fade displacement, a dynamic virtual host receives a `Fork()` copy of the physical/virtual host's *current* prepared DSP histories at the exact frame boundary, while the physical/virtual host retains its original Filter state for subsequent notes. The displaced voice's PCM passes through that fork exactly once, not back through the original host bus. A displaced source can finish before the forked filter tail; the detached dynamic output tail continues with zero input and is counted toward quiescence. Forked histories may duplicate a portion of the already mixed pre-displacement signal—this is expected and explicitly documented, not an attempt to deconvolve earlier voices. Nonlinear saturated-ladder regression tests distinguish filtering a summed host signal from separately filtering its voices; other tests verify NNA state fork and independent subsequent clear, host sharing, scoped virtual isolation, finite tails, flattened-source cancellation and partition invariance in `Heresy.Tests.Render/ChannelOutputFilterRenderingTests.cs`.

## Final speaker-output filters

**Completed 12 October 2026:** The final speaker bank now delegates its processing to the same `StreamingFilterChain` engine used for other serial Filter stages, but owns **one independent, mono processing chain per output speaker** so DSP histories cannot cross speaker feeds. The bank receives exactly one post-master-mix call from the outermost `PlaybackSession.Render`; private recursive sessions deliberately bypass it. `OutputFilterType.None` remains an exact bypass. Existing `LowPass` and `HighPass` values in application preferences remain byte-for-byte compatible in structure and are prepared through the explicit `SpeakerLegacyRc` built-in stage. That RC algorithm computes `alpha=1-exp(-2*pi*f/fs)` and `low'=low+alpha*(input-low)`, outputting `low'` or `input-low'` as appropriate, with the original 1e-7 silent-input clamp. **Normal `OnePole` uses TPT/bilinear coefficients and is not numerically the same at the same cutoff:** the new `SpeakerLegacyRc` Filter kind is its intentionally named exact-equivalence representation and is visible in the catalogue. The new `OutputFilterType.Chain` uses the normal reusable Filter factory (all 22 stages, including a legacy RC option), independent speaker history and bounded DSP tail budgeting.

**Settings transition:** `OutputChannelConfiguration` accepts an inline `FilterInstance` only for Chain mode, freezes a detached copy of the stage definition and all effective typed parameters, and returns clones to callers. The Options → Audio Output editor explicitly labels saved choices **LowPass (RC)** and **HighPass (RC)** and adds **Filter chain → Edit chain…** with one stage per line of catalogue-backed `Kind Parameter=Value …` instructions. ## Rendering, tail and runtime invariants

- DSP preparation respects sample rate, sample count, output channel count and bounded CPU/memory budgets. FIR convolution, state-variable operations and nonlinear oversampling must never use unbounded work. Guard against unstable IIR feedback, NaN/Inf, denormal buildup, invalid high frequencies, and nonphysical parameter ranges.
- Distinguish natural source end from filter residual output. FIR has a finite mathematical delay tail; IIR may decay asymptotically, requiring a documented silence threshold and a bounded drain/retirement policy. A channel filter must be allowed to drain after its input ceases; an active script producing indefinitely is not falsely declared finite. FM graph's explicit Tail is an additional authored lifetime limit as defined above.
- Process channel buffers in a fixed deterministic order; render-block partitioning must not change output. A seek backwards reconstructs immutable preparation and histories by deterministic replay (or later justified bounded checkpoints), never by sharing live states or caching an entire future event stream.
- Reset/rebuild a stage only when its state topology becomes incompatible; preserve compatible state on normal cutoff/Q/gain changes. Native filter changes are event-frame atomic. Freeze live document edits from current playback.
- Preserve channels/spatial output, deterministic diagnostics with rate caps, no crashes on malformed scripts/commands, and existing NNA, pattern preview, Note Off, virtual voice and mixdown rules.

## Live FIR control worker publication — 12 October 2026

Live `BufferedAudioOutputSource` sessions now create a dedicated `FirPreparationScheduler` independently from the SDL callback and the PCM-producing worker. At the end of each PCM quantum, `IFirPreparationAudioSource.QueuePendingFirControls` walks the single owning `PlaybackSession`'s physical, targeted/scoped virtual and displaced/NNA voices. Each note-event/flattened-scope control or FM Filter-node state uses its own bounded `FirPreparationMailbox`. The PCM producer copies only numerical requests (up to four stages under the existing 131,072-work-unit/2-MiB preparation budget), and the worker designs expensive FIR plans against immutable cloned authored configuration, never against mutable DSP histories. At the start of a later PCM quantum, `AdoptPreparedFirControls` obtains immutable candidates; only exact matching stage/parameter sets are committed by the ordinary atomic DSP path. Private recursive mixdowns forward publication to their own active child sessions; backward seek constructs new invocation state and stale old-mailbox results cannot migrate across it. A superseded in-flight snapshot is not published; identical repeated snapshots coalesce so that a continuously offered value does not starve the worker. Errors are surfaced via the preparation worker's `Fault`/live rendering health and new pending versions may recover; old active kernels survive admission limits, misses and overruns. The control thread is joined on host disposal, and callback never waits for kernel preparation.

For moving FIR modulation, the live path captures one absolute target at a bounded producer quantum and **sample-and-holds** it until that target's matching prepared plan is adopted. It does not claim sample-accurate FFT/window design at audio rate. Subsequent targets may be sampled at later quanta. Continuous IIR modulation remains per PCM frame where supported, while coupled IIR/FIR updates retain the all-or-nothing rule. Explicit synchronous off-PCM preparation remains for offline rendering and deterministic boundary replay. The actual kernel-commit wall time depends on worker load and host quantum timing; hardware-wide latency/deadline guarantees and audible acceptance on physical Windows/Linux devices are intentionally not asserted by GitHub Actions. See `docs/filter-realtime-qualification.md` and the separate physical acceptance task.


## Persistent channel-output Filter parameter envelopes — 12 October 2026

`SetChannelFilterParameterEnvelopeCommand(stageId, parameterName, envelopeId?)` is a host-channel analogue of the existing note-local binding command. It attaches/replaces one numeric nonstructural Filter-stage parameter to an already-selected persistent output Filter, or detaches that parameter when `envelopeId` is null. The command targets the **real physical host** regardless of its recursive Pattern/Sequence physical owner, the unscoped targeted virtual host, or the exact (invocation owner, virtual ID) scoped host. The selected host must exist; unknown Filter/Envelope IDs, structural/nonmodulatable stage properties and nonfinite/out-of-range initial curve values are diagnosed without partial publication. An explicit `SetChannelFilterCommand` replace/clear restarts or drops the host binding set, while a typed or multiline parameter assignment modifies the separately authored base without overriding the currently bound absolute envelope values.

The durable `ChannelOutputFilterState` owns the immutable curve references, their absolute attachment frames and release-independent `EnvelopePlaybackState` clocks. The clocks do **not** receive `NoteOff` when unrelated notes end. `ProcessInterleaved` samples all active bindings at each absolute session frame of the **already summed channel feed**, exactly once for that host and speaker frame. It uses the prevalidated, allocation-free numeric `NoteFilterEnvelopeRealtimeControls` pathway to publish combined IIR/Comb/FIR changes atomically, retaining matched histories and 32-frame smoothing. One invalid runtime envelope proposal holds the last accepted response; per-host runtime diagnostics are emitted once per binding generation (the shared recursive-sequencing diagnostic sink additionally limits channel warning volume). A host persists through new notes and flattened scope cancellation, and its forked NNA virtual output keeps independent clocks, accepted values and history. The next separately tracked NNA milestone covers complete cross-host continuity/behavior acceptance.

Binding and detachment update the controller transactionally **without configuring kernels on the PCM producer**. The new controller inherits the previous accepted numeric targets alongside the forked DSP history; a missing binding is restored to the latest authored base by the next legal PCM update. A newly attached or detached FIR target is not prepared via synchronous `Configure`: it remains on the old valid kernel until an explicitly scheduled bounded off-PCM preparation is available. Other authored base edits construct an effective successor configuration that overlays only still-bound accepted targets, compare full parameter/stage snapshots before calling `Configure`, and avoid restarting smoothing if an underlying bound base edit does not change the audible effective target. This is deliberately distinct from note-event Filter Envelopes, which follow their own note release. The automated PCM regressions exercise note lifecycle, cross-owner physical and scoped virtual routing, chunk partitions, envelope invalidity, text/typed updates under active bindings, exact detach restoration and FIR hold/prepare semantics. Hardware/device listening remains separately unchecked.


## NNA output Filter deep-fork acceptance — 12 October 2026

**Implementation and ownership verified:** The displaced note is the original `PlaybackVoice`, not a synthesized replacement. On Continue, Off (when an audible displaced lifecycle remains), and Fade, `PlaybackSession.DisplaceCurrentVoice` detaches that note from its logical playback channel and obtains `ForkHostFilter` using the *actual originating output host*: physical host ID, unscoped targeted virtual ID, or (invocation owner, virtual ID) for a scoped host. The host's `ChannelOutputFilterState.Fork()` deep-forks the serial `StreamingFilterChain` (including independent speaker histories, delay rings, convolution state and active interpolation), copies the immutable-by-clone authored Filter configuration, and binds an independent per-host Envelope controller to the original absolute attachment frames. Existing accepted effective numeric targets are copied from the original controller; the previous active host is never overwritten. The original voice and its tone/event/flattened-source Filter chains are moved intact into `_virtualVoices`. Its PCM is filtered through the new dynamic host exactly once. On completed source playback, any still-active dynamic Filter tail moves to the separate displaced-tail collection and drains using silent input without touching the physical or scoped original host.

**Exact boundary qualification:** `ChannelFilterNnaForkTests` compare paired stereo Filter hosts after a shared input history and an actual fork, including the **first output frame** on the new host. Further input/structural parameter edits prove the two forks diverge independently. A live `PlaybackSession` regression checks the precise displaced virtual-host PCM contribution on a same-frame physical-host re-selection and identical whole-block versus split-block output. Other tests verify an active numeric parameter Envelope mid-way through a coefficient ramp, an independent physical detach, original note-event Filter-chain reference identity, Continue/Off/Fade paths and two separate recursive owners reusing one virtual-channel ID. **Important nuance:** the historical signal contributed to an original host before displacement is represented in *both* independent continuation histories afterward, because the complete host state is cloned. This intentionally does not mathematically isolate prior voices from one another; an old ring tap may therefore emit once on each branch. New notes and subsequent authored commands change only their own host state. No extra private mixdown, PCM replay, history reset or double routing through the source host is introduced. The separate physical Windows/Linux listening task remains open.

### Runtime-tolerant Filter assignment text; strict authoring (13 October 2026)

Native **Set Channel Filter Stage Assignments** and **Set Note Filter Stage
Assignments** effects still persist their original multiline
`stageName.parameterName = value` text and optional editor-only Filter
selection hint; neither song format nor typed-parameter commands change.
There are deliberately **two interpretations** of this language:

- **Strict authoring**: `FilterAssignmentText.ParseAndValidate` and
  `ApplyToClone` remain unchanged. Invalid lines, duplicate assignments,
  unknown stages/properties, out-of-range numbers, unsupported choices and
  invalid FIR band-edge combinations produce diagnostics rather than a
  false assurance that the authored script is completely correct. The
  per-stage assistant still previews valid rows, retains formatting,
  updates existing rows in place and leaves unrelated text alone.
  The native effect dialog displays the strict diagnostic **on the
  first Apply/Insert**. An identical second Apply/Insert explicitly saves
  the draft intact, understanding that runtime will skip bad lines; any
  change in the authored text, Filter ID or effect type resets that
  confirmation. A missing/wrong Filter selection and empty text remain
  errors, including on a confirmed draft.
- **Tolerant runtime**: `FilterAssignmentText.ApplyValidToClone` resolves
  stage names, canonical descriptor names and invariant-culture numeric
  and choice values independently. Blank/comment rows, malformed
  syntax, unknown stages/properties, invalid or nonfinite numbers,
  invalid choices/ranges and unpreparable DSP values are **silently
  ignored**. A later valid duplicate takes precedence, but an invalid
  duplicate never erases an earlier valid row. The last valid values
  for a stage are grouped and validated as a complete atomic batch,
  so simultaneously moving both FIR cutoffs across existing limits
  works when their *new pair* is valid. If the new pair conflicts,
  retain the earlier independently valid cutoff before attempting
  the later one; keep unrelated valid properties in the same stage
  and across other stages.
  
  The prepared runtime can additionally provide a nonpublishing DSP
  suitability check at the actual sample rate. If a field passes Core
  descriptors but cannot produce a legal DSP plan (e.g. cutoff at or
  above Nyquist), runtime tries whole-stage candidate batches and
  then smaller subsets to retain independently preparable changes.
  The control-side tests fork histories and prepare plans only **at
  the command boundary**, never in per-sample processing. Rejected
  candidate plans, stage edits and intermediate coefficient states
  are discarded; only the complete, fully preflighted successor
  configuration and forked DSP histories may be published.

A text effect with no accepted semantic changes is a true runtime no-op:
it neither replaces the selected channel state nor publishes a new
note/flattened-source DSP snapshot. A text effect with some accepted
changes publishes those changes atomically, respecting same-frame
effect order, physical/scoped virtual host selection, and Note Filter
scope. For flattened recursive sources, *all descendants* must
pass preparation before any descendant or instigator controller
is modified. Invalid **individual text fields** do not invoke
`ChannelFilterCommandRejected` or `NoteFilterCommandRejected` and
do not add `HRSEQ007/HRSEQ009` entries; genuine structural targeting
errors such as no selected Filter retain their existing diagnostics.
Unlike tolerant text, the existing *typed* stage commands intentionally
continue rejecting an invalid entire typed batch atomically.

Regressions include Core mixed valid/invalid lines, canonical duplicate
ordering, valid and conflicting FIR cutoff pairs and an injected
sample-rate rejection; Channel and Note PCM equivalence against typed
commands with independently unsupported cutoff and valid mode;
intact channel history/structural response; recursive Data Pattern
execution without a warning; flattened multi-descendant versus sibling
routing; authoring API strict/permissive differentiation and headless
two-step dialog confirmation, including stale-draft and wrong-Filter
safety. The original selected Filter instance and its snapshot remain
unchanged by parsing or by abandoned control-side preflight trials.

## Absolute song-time alignment and export qualification (14 October 2026)

**Qualified without changes to audio implementation.** A text-selected
Envelope is bound at the frame of the **executed assignment command**;
the mechanism reuses the same `SetNoteFilterParameterEnvelopeCommand` /
`SetChannelFilterParameterEnvelopeCommand` handlers as explicitly typed
modulation. Its phase does not start when the containing note was first
created unless the assignment was itself executed at that moment. The
per-Envelope state holds an attachment frame and derives elapsed Envelope
time from the current render frame minus that attachment frame. For root
sessions these are song-frame coordinates; private recursively mixed
sessions have invocation-local frame coordinates whose origin is translated
with the parent start. The elapsed-time difference is invariant under that
translation. This is an *effective musical-time* guarantee, not a claim
that every private renderer stores parent absolute frames internally.

**Note scope:** Event Filter bindings are attached to the current logical
note or its flattened source controller. A late Note Off releases the
parameter Envelope according to that same note's lifetime; an NNA-forked
voice retains its prior binding and a later note does not acquire it.
A flattened controller records the original binding frame; both active
descendants and descendants started later use that original origin.
**Channel scope:** Each physical/scoped host has its own independent
attachment frame. Channel Envelope progress persists across unrelated note
starts and is not reset at those notes' sample-local time zero.

**Automated evidence:** `NoteFilterParameterEnvelopeTests` compares
text-selected, explicitly typed and exact frame-by-frame numerical
controls for late Note attachment (note starts at frame 1, binding at
frame 5); verifies sample-exact output across different render blocks,
late Channel attachments and independent physical hosts, release then
replacement, NNA continuation, flattened controllers with a child begun
*after* the attachment, and the existing FIR design/adoption boundary
outside the PCM loop. `PreparedIncrementalPlaybackFactoryTests` compares
two-row-shifted Data Pattern roots and nested private mixdowns, their
offline-style bulk versus realtime-style partitioned renders, and
private source-frame forward seeking/backward reconstruction with an
*audible* reference against otherwise identical constant-parameter
Filtering. `WaveOfflineRenderTests` verifies the WAV PCM samples
produced by the actual offline export pipeline against a separately
rendered live reference whose text-selected Envelope begins at a
nonzero song frame. Matching outputs include the same note/speaker
Filter processing and event ordering, with no fabricated Envelope
samples or live-song name lookups during PCM rendering.

No changes to Filter DSP, JSON, source-memory attribution or runtime
clock math were required once the fixtures used a genuinely wet
audible Filter. This is automated parity/transport qualification,
not a claim of completed speaker-device listening tests. The
`THEN OFF`/`THEN CUT` Envelope-end actions remain the next independent
implementation task.
